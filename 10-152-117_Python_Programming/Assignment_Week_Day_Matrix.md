# ASSIGNMENT WEEK-DAY MATRIX

**10-152-117 Python Programming**

---

# Purpose

This artifact maps the assignment sequence onto the actual week/day rhythm of the course.

It is intended as an instructor planning tool for:

* pacing
* assignment release timing
* lab emphasis
* due-date planning
* seeing where multi-session work is likely to occur

This is a **recommended instructional map**, not a rigid lock.

Some assignments are intentionally small enough to fit in one session.
Others benefit from a launch session followed by a continuation or completion session.

---

# Course Rhythm

* **Meeting Pattern:** Monday, Tuesday, Thursday
* **Time:** `10:30 AM - 12:23 PM`
* **Course Dates:** `August 17, 2026` through `October 8, 2026`

# Reading the Matrix

Use the assignment action labels as planning guidance:

* **Launch** = introduce and begin the assignment
* **Build** = main work period
* **Continue** = extend or complete ongoing work
* **Submit / Review** = checkpoint, approval, presentation, or completion point

# Instructor Notes

## Why Some Weeks Carry Two Assignments

This course uses short targeted assignments rather than one long-running student project.

That means some weeks naturally hold:

* one assignment that launches early and closes later
* one second assignment that begins once the first concept is established

This is especially true in:

* Week 2
* Week 3
* Week 4
* Week 5
* Week 6
* Week 7

## Why Week 8 Is Simpler

Week 8 shifts from isolated concept work into:

* integrated build
* testing and validation
* explanation
* presentation

That is why the assignment map compresses into:

* A15 - build
* A16 - explain and present

## Use as a Planning Tool

This matrix is especially useful when deciding:

* when to release assignment instructions
* when to show demos
* when to use success examples
* where lab-heavy sessions should dominate
* where proposal review or scope-control conversations should happen
