# AI Use Justification Guide

---

# Purpose

This guide defines how students should explain and justify their use of AI in `10-152-117 Python Programming`.

The goal is not to punish AI use.

The goal is to make AI use:

* visible
* explainable
* accountable
* tied to student decision-making

In this course, students may use AI in bounded ways, especially in later project work and the capstone. However, students are still responsible for understanding, validating, and explaining the final result.

---

# Core Principle

Using AI does not remove authorship responsibilities.

If a student uses AI, the student must still be able to explain:

* what they were trying to do
* why they used AI
* what AI contributed
* what they changed
* how they tested the result
* what decisions remained human decisions

---

# Why This Matters

This guide exists to reinforce the course expectation that students should not simply generate code and submit it without understanding it.

The justification process helps students demonstrate:

* code comprehension
* responsible tool use
* debugging and validation habits
* ownership of project decisions
* the difference between assistance and dependence

This also supports stronger capstone review because the instructor can evaluate not only what the student built, but how the student governed the development process.

---

# When Students Should Use This

This justification process should be used:

* for the capstone project
* for any major project where AI assistance was used
* when the instructor requests an explanation of AI involvement

It may also be used for selected labs if AI use becomes part of the assignment.

---

# Required Student Questions

Students should answer the following questions clearly and honestly.

## 1. What were you trying to build?

Describe the program, feature, or problem in plain language.

Good responses explain:

* the project goal
* the user-facing behavior
* the intended inputs and outputs

Example:

> I was building a task tracker that lets a user add tasks, mark them complete, and save them to a file.

---

## 2. What did you use AI for?

Describe the specific role AI played.

Examples:

* brainstorming possible approaches
* generating a first draft of a function
* debugging an error
* explaining unfamiliar syntax
* refactoring code for readability
* helping structure API request code

Students should avoid vague statements such as:

* "I used AI to help with the whole project"

Instead, they should identify concrete uses.

---

## 3. What did AI produce?

Describe what the AI actually gave back.

Examples:

* a draft function
* a class-based version of a program
* a debugging suggestion
* a revised loop
* file-handling logic
* API request and parsing code

This helps distinguish AI contribution from student contribution.

---

## 4. What did you keep, change, or reject?

This is one of the most important parts of the guide.

Students should explain:

* what AI output they accepted
* what they modified
* what they decided not to use

Examples:

* I kept the file-reading logic but changed the variable names and the error handling.
* I rejected the class-based version because my project was small and a function-based approach was clearer.
* I used the loop pattern from AI, but rewrote the condition because the original logic was wrong.

This section shows whether the student exercised judgment.

---

## 5. How did you verify that the code worked?

Students must explain how they checked correctness.

Possible forms of verification:

* running test inputs
* tracing logic by hand
* checking edge cases
* printing intermediate values
* comparing expected and actual output
* fixing errors after execution

Students should be able to describe the validation process, not just say:

* "It worked"

---

## 6. What decisions were still yours?

Students should identify the important human decisions they made.

These might include:

* choosing the project scope
* deciding the program structure
* choosing between functions and classes
* selecting what features to include
* deciding which AI suggestions were acceptable
* simplifying or expanding the project
* determining what counted as success

This question reinforces that AI assistance does not replace student judgment.

---

## 7. What did you learn from using AI on this task?

Students should briefly reflect on the development process.

Possible topics:

* where AI was useful
* where AI was confusing or incorrect
* what required manual correction
* what they would do differently next time

This reflection helps students move from passive use toward intentional use.

---

# Recommended Format

Students do not need to write a long essay.

A short structured write-up is enough if it is specific and honest.

Recommended length:

* `1/2 page to 1 page` for most projects
* longer only if the instructor requests a fuller reflection

---

# Suggested Student Template

Students may use the following structure:

## AI Use Justification

**Project Name:**  

**1. What I was trying to build:**  

**2. What I used AI for:**  

**3. What AI produced:**  

**4. What I kept, changed, or rejected:**  

**5. How I tested or verified the code:**  

**6. What decisions were still mine:**  

**7. What I learned from using AI on this project:**  

---

# Example Response

## AI Use Justification

**Project Name:** Weather Lookup Tool

**1. What I was trying to build:**  
I was building a program that lets a user enter a city and then returns current weather information from an API.

**2. What I used AI for:**  
I used AI to help draft the API request code and explain how to access values from the JSON response.

**3. What AI produced:**  
AI produced a sample request using a weather API and a code example that pulled out temperature and condition fields.

**4. What I kept, changed, or rejected:**  
I kept the general request structure, but changed the variable names, added input validation, and rewrote the error handling. I rejected one version that used a class because it was more complex than I needed.

**5. How I tested or verified the code:**  
I tested the program with valid and invalid city names, printed the JSON once to inspect the structure, and checked whether the output matched what I expected.

**6. What decisions were still mine:**  
I chose the project idea, selected the features, decided to keep the program function-based, and decided what to keep from the AI output.

**7. What I learned from using AI on this project:**  
AI was useful for getting started with the API request, but I still had to inspect the response, fix errors, and simplify the structure so I could explain it clearly.

# Instructor Review Focus

When reviewing an AI use justification, the instructor should be able to see:

* whether the student understands the project they built
* whether the student can identify the actual role AI played
* whether the student made real decisions rather than copying blindly
* whether the student validated the work
* whether the student can explain the final result clearly

The strongest justifications usually include:

* specific examples
* honest mention of confusion or revision
* evidence of testing and choice-making

Weak justifications usually sound vague, generic, or overly passive.

---

# What This Is Not

This guide is not:

* a confession form
* a punishment mechanism
* a requirement to avoid AI completely

It is an accountability and explanation tool.

Used correctly, it helps students show that they did not just use AI, but governed its use responsibly.

---

# Relationship to RBA

This guide also supports the later RBA mini-unit and capstone work.

It reinforces key habits that matter in RBA-aligned development:

* intent before generation
* human judgment over output acceptance
* validation after implementation
* explanation of decisions

Students do not need formal RBA terminology in the justification, but the process aligns well with the course expectation that AI should remain bounded by human understanding and decision-making.

---

# Most Important Outcome

A student who uses AI in this course should still be able to say:

> "I can explain what I built, why I used AI, what I changed, and why the final result is still my work."
