# 3. Opening Frame (2-4 minutes)

Today is about code literacy, not class mastery.

Key message:

* students will encounter code written in different organizational styles
* AI often returns class-based code
* students need to recognize and explain it without freezing

Suggested wording:

> "You do not need to become an object-oriented theory expert today. You do need to be able to read a small class-based example and explain what it is doing."

---

# 4. Course Positioning (2-4 minutes)

Students now know:

* how programs can be structured with functions
* how data can be stored in collections

Today adds:

* procedural versus function-based versus class-based comparison
* attributes and methods in plain language
* interpretation of common AI-generated structure

Suggested wording:

> "This session builds on last week's structure work. The goal is not to replace procedural thinking, but to recognize another common way code may be organized."

---

# 5. Core Concepts (10-20 minutes)

## Concept 1 - Code can be organized in more than one style

Plain-language explanation:

* one task can be written procedurally, with functions, or with a class

Why it matters:

* students need flexibility in reading unfamiliar code

## Concept 2 - A class groups related data and actions

Plain-language explanation:

* the class stores information and defines actions that belong with it

Why it matters:

* this is the simplest useful beginner-level explanation

## Concept 3 - `__init__` sets up starting state

Plain-language explanation:

* `__init__` runs when the object is created
* it stores starting values

Why it matters:

* this is a key recognition target when students inspect AI-generated code

## Concept 4 - Attributes and methods are readable in plain language

Plain-language explanation:

* attributes are stored values
* methods are actions the object can do

Why it matters:

* students should be able to narrate the code without formal theory language

# 7. Hands-On / Lab Bridge (10-20 minutes)

Students should try:

* identifying the class name
* identifying attributes
* identifying methods
* making one small modification
* comparing it to the function-based version

Suggested wording:

> "Your goal today is not to design a class hierarchy. Your goal is to read a small class-based program, explain its parts, and make one working change."

Do not require:

* inheritance
* polymorphism theory
* advanced class behavior

---

# 8. Common Mistakes / Watch-Fors (5-8 minutes)

## Mistake 1 - the class feels more mysterious than it is

Why it happens:

* students may treat the word `class` as if it signals advanced hidden behavior

Correction:

* translate everything into plain language immediately

## Mistake 2 - `__init__` is seen as magic syntax

Why it happens:

* it looks unfamiliar and formal

Correction:

* explain it as the setup step when an object is created

## Mistake 3 - students assume class-based means better by default

Why it happens:

* AI output may look more sophisticated

Correction:

* compare styles in terms of fit, not prestige

---

# 9. Explain / Checkpoint Questions (3-8 minutes)

Ask:

* What does this class store?
* What does this method do?
* What happens when the object is created?
* How is this different from the function-based version?

---

# 10. End-of-Class Success Check

> By the end of this session, students should be able to identify the main parts of a small class-based program, explain them in plain language, and make a small modification without treating the structure as mysterious.
