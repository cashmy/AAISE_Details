# 3. Opening Frame (2-4 minutes)

Today shifts from "code that works" to "code that is easier to manage."

Key message:

* repeated code becomes a problem
* functions give parts of the program a name and a purpose
* organization is a programming skill, not decoration

Suggested wording:

> "This week is where your code starts becoming shaped instead of just accumulated. We are naming responsibilities so the program is easier to understand and change."

---

# 4. Course Positioning (2-4 minutes)

Students now know:

* variables
* expressions
* conditions
* loops

Today adds:

* functions as reusable named logic
* parameters and return values as controlled input/output inside the program

Suggested wording:

> "So far, you have been writing working code mostly in one block. Today we begin breaking that work into named pieces with clearer responsibility."

---

# 5. Core Concepts (10-20 minutes)

## Concept 1 - Repeated code is a sign to organize

Plain-language explanation:

* when the same steps appear more than once, the program gets harder to maintain

Why it matters:

* students need to see the reason for functions before learning the syntax

## Concept 2 - A function is a named unit of responsibility

Plain-language explanation:

* a function groups steps that belong together
* the name should explain the function's job

Why it matters:

* Assignment 4 depends on students being able to explain purpose, not just define syntax

## Concept 3 - Parameters bring values in

Plain-language explanation:

* a parameter gives a function the value it needs to work with

Why it matters:

* this is how functions stay reusable

## Concept 4 - Return values send results back

Plain-language explanation:

* some functions compute a result and give it back to the program

Why it matters:

* students need a beginner-level sense of data flow within a structured program

# 7. Hands-On / Lab Bridge (10-20 minutes)

Students should try:

* refactoring a previous small program into functions
* building a tiny utility with 2 functions
* separating calculation from display

Suggested wording:

> "Your goal today is not to create many functions. Your goal is to create a few functions where each one has a clear job and a name that makes sense."

Do not require:

* large multi-file structure
* deep nesting
* advanced return-value chains

---

# 8. Common Mistakes / Watch-Fors (5-8 minutes)

## Mistake 1 - making functions without a clear purpose

Why it happens:

* students may split code randomly instead of by responsibility

Correction:

* ask: what job does this function own?

## Mistake 2 - function names are vague

Why it happens:

* students may use generic names that do not help readability

Correction:

* require names that describe the actual action or result

## Mistake 3 - parameters and return values blur together

Why it happens:

* students are still learning value flow inside structured code

Correction:

* narrate: what comes in, what happens, what comes out

---

# 9. Explain / Checkpoint Questions (3-8 minutes)

Ask:

* What is this function responsible for?
* What value comes into this function?
* What result comes out?
* Why is this clearer than one long repeated block?

---

# 10. End-of-Class Success Check

> By the end of this session, students should be able to place repeated or related logic into a few functions and explain what each function is responsible for.
