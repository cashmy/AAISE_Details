# 3. Opening Frame (2-4 minutes)

Today moves from organizing logic to organizing information.

Key message:

* a program often needs to remember more than one value
* related values can be stored together
* lists and dictionaries make a program feel more useful

Suggested wording:

> "Once a program starts keeping track of information, it begins to feel more like a tool than a single-use script."

---

# 4. Course Positioning (2-4 minutes)

Students now know:

* how to write functions
* how to name responsibilities

Today adds:

* lists for grouped items
* dictionaries for labeled values
* iteration over stored data

Suggested wording:

> "Yesterday we organized the logic. Today we organize the data the logic needs to work with."

---

# 5. Core Concepts (10-20 minutes)

## Concept 1 - Lists hold multiple related items

Plain-language explanation:

* a list is useful when the program keeps a group of values together

Why it matters:

* students need a practical mental model for collections

## Concept 2 - Dictionaries label values by meaning

Plain-language explanation:

* a dictionary connects a name or key to a value

Why it matters:

* many mini-apps and later JSON/API tasks depend on key-based access

## Concept 3 - Iteration makes stored data useful

Plain-language explanation:

* once values are stored together, the program can loop through them

Why it matters:

* collection storage without access and display is not yet very useful

## Concept 4 - Structured data supports mini-app thinking

Plain-language explanation:

* lists and dictionaries help small programs keep state and respond in more realistic ways

Why it matters:

* Assignment 5 should feel like a tiny useful tool, not a syntax drill

# 7. Hands-On / Lab Bridge (10-20 minutes)

Students should try:

* a simple task list
* a score tracker
* an item lookup
* a menu selector

Suggested wording:

> "Your goal today is not to build a giant app. Your goal is to store related information in a structure you can actually use, display, and explain."

Do not require:

* file saving yet
* large nested data
* too many features in one mini-app

---

# 8. Common Mistakes / Watch-Fors (5-8 minutes)

## Mistake 1 - storing data without a plan for using it

Why it happens:

* students may create a list or dictionary but not connect it to output

Correction:

* ask: what useful thing will the program do with this stored data?

## Mistake 2 - dictionary keys are treated like list positions

Why it happens:

* students are still learning the difference between indexed and labeled access

Correction:

* contrast list indexing and dictionary key lookup directly

## Mistake 3 - too much nested structure too soon

Why it happens:

* students may overbuild as soon as they see the power of collections

Correction:

* keep the mini-app small and readable

---

# 9. Explain / Checkpoint Questions (3-8 minutes)

Ask:

* Why did you use a list here?
* Why would a dictionary help in this example?
* How do you get one value back out?
* What does the loop do with the stored data?

---

# 10. End-of-Class Success Check

> By the end of this session, students should be able to store related values in a list or dictionary, retrieve useful information, and loop through that data in a small mini-app context.
