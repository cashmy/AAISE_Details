# 3. Opening Frame (2-4 minutes)

Today moves students from static scripts into programs that can make choices.

Key message:

* a program does not always have to do the same thing
* code can choose between outcomes
* logic controls the path

Suggested wording:

> "Last week, your programs produced output. This week, your programs start making decisions about what output should happen."

# 4. Course Positioning (2-4 minutes)

Students now know:

* how to print output
* how to store values in variables
* how to move values through simple expressions

Today adds:

* comparisons
* true/false thinking
* branching with `if`, `elif`, and `else`

Suggested wording:

> "So far, your programs mostly followed one straight path. Today we add logic so the program can choose between different outcomes."

---

# 5. Core Concepts (10-20 minutes)

## Concept 1 - Comparisons produce true or false results

Plain-language explanation:

* code can compare values
* the result of a comparison is a boolean idea: true or false

Why it matters:

* branching depends on a condition being checked

## Concept 2 - `if` runs code only when a condition is true

Plain-language explanation:

* `if` creates a conditional path
* the program does not run every line in every situation

Why it matters:

* Assignment 2 depends on students understanding why one outcome appears instead of another

## Concept 3 - `elif` and `else` give alternate paths

Plain-language explanation:

* `elif` checks another condition
* `else` catches the remaining case

Why it matters:

* students need to see branching as a small system, not a random stack of lines

## Concept 4 - Prediction comes before execution

Plain-language explanation:

* before running the code, students should ask which path will happen

Why it matters:

* this builds reasoning rather than trial-and-error habits

# 7. Hands-On / Lab Bridge (10-20 minutes)

Students should try:

* a grading checker
* a discount checker
* an eligibility checker
* a recommendation tool

Suggested wording:

> "Your goal today is not to write a complicated program. Your goal is to write a small program where you can explain why one branch ran instead of another."

Do not require yet:

* loops
* menus
* multi-feature programs

---

# 8. Common Mistakes / Watch-Fors (5-8 minutes)

## Mistake 1 - confusing assignment and comparison

Why it happens:

* students see `=` and `==` as visually similar

Correction:

* show their roles side by side and explain the different jobs clearly

## Mistake 2 - thinking every branch runs

Why it happens:

* students may read code as if all lines always execute

Correction:

* repeatedly ask: which path is active in this case?

## Mistake 3 - conditions are written but not understood

Why it happens:

* students may copy a comparison without understanding what it tests

Correction:

* require plain-language narration of the condition

---

# 9. Explain / Checkpoint Questions (3-8 minutes)

Ask:

* What is this condition checking?
* Is the condition true or false for this value?
* Which branch will run?
* Why does the program show this output instead of the other one?

---

# 10. End-of-Class Success Check

> By the end of this session, students should be able to write a small `if`-based program, predict which branch will run, and explain why that path was selected.
