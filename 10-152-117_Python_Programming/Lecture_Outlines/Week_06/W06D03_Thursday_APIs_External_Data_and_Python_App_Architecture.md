# 4. Course Positioning (2-4 minutes)

Students now know:

* how Python can work with external data
* how structured responses are read and used

Today adds:

* application-layer separation
* MVT recognition
* templates, forms, and views as larger-structure ideas

Suggested wording:

> "So far, most of your Python work has lived in one script. Today we look at how larger systems separate user input, data handling, logic, and display."

---

# 5. Core Concepts (10-20 minutes)

## Concept 1 - Larger applications separate responsibilities

Plain-language explanation:

* input, validation, logic, and display do not all have to live in one block

Why it matters:

* this is the core architecture insight students should retain

## Concept 2 - MVT is a useful recognition model

Plain-language explanation:

* models represent data
* views handle logic or request flow
* templates display output

Why it matters:

* Assignment 12 depends on recognition of the flow, not implementation mastery

## Concept 3 - Forms help shape and validate input

Plain-language explanation:

* forms are not only UI fields
* they also help control and validate what enters the system

Why it matters:

* this helps students see where input checking can live in a larger application

## Concept 4 - This is a preview, not a new burden

Plain-language explanation:

* students are expected to identify parts and explain the flow
* they are not expected to build a full Django project here

Why it matters:

* bounded expectations prevent unnecessary overload

# 7. Hands-On / Lab Bridge (10-20 minutes)

Students should try:

* identifying where input enters the system
* identifying where validation happens
* identifying where display output lives
* explaining the flow in plain language

Suggested wording:

> "Your goal today is not to build Django. Your goal is to recognize how a larger Python application separates responsibilities and to explain that flow clearly."

Do not require:

* framework installation
* project scaffolding
* routes, settings, and migrations in full detail

---

# 8. Common Mistakes / Watch-Fors (5-8 minutes)

## Mistake 1 - students assume this is now a full web-development turn

Why it happens:

* words like Django, template, and form sound like a major course shift

Correction:

* keep repeating that this is a recognition bridge

## Mistake 2 - the flow remains vague

Why it happens:

* students may memorize terms without seeing how the pieces connect

Correction:

* insist on plain-language flow explanations

## Mistake 3 - console scripts and app architectures are treated as unrelated worlds

Why it happens:

* students may not see the continuity

Correction:

* compare one small tool in both styles and show the relationship

---

# 9. Explain / Checkpoint Questions (3-8 minutes)

Ask:

* Where does user input enter this system?
* Where is that input validated?
* Where does the logic happen?
* Where is the output displayed?
* How is this different from a console-only script?

---

# 10. End-of-Class Success Check

> By the end of this session, students should be able to explain, in plain language, where input, validation, logic, and display live in a larger Python application flow and how that differs from a console script.
