# 3. Opening Frame (2-4 minutes)

Today is the first small integration day.

Students have seen:

* text
* variables
* numbers
* simple expressions
* optional input

Now the goal is to combine them in small practical scripts.

Suggested wording:

> "Today is where the first week comes together. We are not adding a huge amount of new material. We are combining the pieces you already have into small useful programs."

---

# 4. Course Positioning (2-4 minutes)

This session should connect back to the entire week:

* Monday established that a program can run and produce output
* Tuesday showed value change and simple calculations
* Thursday asks students to combine those pieces in a manageable way

Suggested wording:

> "This week is not about mastering all of Python. It is about becoming comfortable with the smallest useful pieces so you can build and explain very small working programs."

# 5. Core Concepts (10-20 minutes)

## Concept 1 - Type awareness through use

Plain-language explanation:

* strings, numbers, and booleans behave differently in code
* students do not need a massive taxonomy yet

Why it matters:

* Assignment 1 needs practical use, not a textbook inventory

## Concept 2 - Combining values in one small script

Plain-language explanation:

* a program may use more than one kind of value at once
* the important thing is whether students can still explain the flow

Why it matters:

* first small integration is the bridge from isolated examples to assignment completion

## Concept 3 - Readability and explainability matter early

Plain-language explanation:

* a short program can still be messy or confusing
* clear names and visible output help students explain what happened

Why it matters:

* confidence comes from understanding, not only from getting output once

# 7. Hands-On / Lab Bridge (10-20 minutes)

Students should complete:

* 2-3 very small programs
* each one with visible output
* each one understandable enough to explain

Suggested wording:

> "Your goal today is not to impress anyone with complexity. Your goal is to finish small programs that run, make sense, and that you can talk through step by step."

Good options:

* greeting or introduction program
* simple calculator
* unit converter
* total-cost estimator
* personalized message builder

---

# 8. Common Mistakes / Watch-Fors (5-8 minutes)

## Mistake 1 - trying to include too much

Why it happens:

* students may think a "real program" must be large

Correction:

* reinforce that Week 1 success is small, working, and explainable

## Mistake 2 - using concepts they cannot explain yet

Why it happens:

* students may copy patterns that are beyond their understanding

Correction:

* require them to narrate inputs, values, expressions, and outputs

## Mistake 3 - drifting into textbook breadth

Why it happens:

* the course description includes "data types," which can tempt overcoverage

Correction:

* keep focus on the smallest useful subset needed for Assignment 1 success

---

# 9. Explain / Checkpoint Questions (3-8 minutes)

Ask:

* What inputs or starting values does this program use?
* What output does it produce?
* Where does the value change?
* Why is this still a successful program even though it is small?
* Could you explain this script line by line to someone else?

---

# 10. End-of-Class Success Check

> By the end of this session, students should be able to complete 2-3 very small practical Python programs and explain the role of each main value, expression, and output.
