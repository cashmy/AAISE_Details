This is the first day of the course, so positioning should be reassuring and concrete.

Key points:

* the course will build gradually

* success today is small but important

Suggested wording:

> "This course builds outward from very small working programs. We are starting with the smallest useful pieces first so you can actually understand what the code is doing."

# 5. Core Concepts (10-20 minutes)

## Concept 1 - A program is a set of instructions

Plain-language explanation:

* Python follows instructions line by line
* the computer is not guessing what we mean

Why it matters:

* students need a mental model before syntax details feel meaningful

## Concept 2 - `print()` makes output visible

Plain-language explanation:

* `print()` displays text or values
* it is one of the fastest ways to see that a program is doing something

Why it matters:

* visible feedback reduces fear and gives immediate payoff

## Concept 3 - Strings are text values

Plain-language explanation:

* a string is text inside quotes
* Python treats `"Hello"` differently from a bare word

Why it matters:

* students need to see what a value looks like before variables make sense

## Concept 4 - Variables store values

Plain-language explanation:

* a variable is a name that points to a value
* the value can later be printed or reused

Why it matters:

* Assignment 1 requires students to store and use values, not just print fixed text

## Demo 1

# 7. Hands-On / Lab Bridge (10-20 minutes)

Students should try:

* a greeting message
* printing their name or a course name
* assigning text to a variable and printing it

Suggested wording:

> "Your goal today is not to build something impressive. Your goal is to make a tiny program run, change one value, and explain what changed in the output."

Do not require:

* `input()`
* numeric calculations
* multiple concepts stacked together

---

# 8. Common Mistakes / Watch-Fors (5-8 minutes)

## Mistake 1 - forgetting quotes around text

Why it happens:

* students see words on the screen and assume plain text does not need markers

Correction:

* show the difference between quoted text and an unquoted name

## Mistake 2 - assuming a variable is "magic"

Why it happens:

* students may think the name itself is the value

Correction:

* say explicitly: the variable is the label, the string is the stored value

## Mistake 3 - setup frustration becomes the whole lesson

Why it happens:

* day-one environment friction can consume confidence

Correction:

* normalize syntax mistakes and setup issues
* keep the emotional target small and winnable

---

# 9. Explain / Checkpoint Questions (3-8 minutes)

Ask:

* What does `print()` do?
* What is the value in this variable?
* If I change the value of the variable, what changes in the output?
* Why does Python need quotes around text?

---

# 10. End-of-Class Success Check

> By the end of this session, students should be able to run a tiny Python program, print text, store text in a variable, and explain what the variable is storing.
