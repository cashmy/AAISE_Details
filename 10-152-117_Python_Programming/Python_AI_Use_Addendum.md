This addendum applies the [Standard Student AI Use Policy](D:\@Artifact_Generation\108_AAISE_Details\Standard_Student_AI_Use_Policy.md:1) to `10-152-117 Python Programming`.

It defines how the general standard is implemented in this specific course.

Where this addendum is more specific than the standard policy, this addendum takes precedence for this course.

---

# Course Position

This course teaches Python first.

AI-assisted development is part of the course, but AI is introduced deliberately and in stages.

Students are expected to learn how to:

* write basic Python programs independently
* use AI support responsibly when allowed
* adapt AI-generated code to meet requirements
* test and debug their programs
* explain their code clearly

---

# Manual-First Expectations in This Course

This course includes a strong manual-first opening sequence.

In the early part of the course, students are expected to build foundational skills without normal AI-supported assignment work.

This is intentional.

The purpose is to help students build:

* confidence
* logic tracing ability
* basic syntax fluency
* debugging habits

without immediately turning AI into a shortcut.

---

# AI Progression in This Course

## Early Course

AI is not a normal student tool for core assignment work in the earliest part of the course.

Instructor demonstration may occur, but students should not assume open AI use by default.

## Middle Course

AI may be allowed in bounded ways for:

* comparison with a manual baseline
* explanation of unfamiliar code
* debugging support after manual diagnosis is attempted
* limited code revision or refactoring

## Later Course

AI may be used more strategically for:

* file and data handling support
* API-related scaffolding
* project refinement
* capstone feature extension

Even then, AI use must remain bounded by student understanding, testing, and explanation.

---

# AI Restrictions in This Course

In this course, students may not:

* use AI to bypass manual-first assignments or restricted labs
* submit Python code they cannot trace or explain
* treat AI-generated output as automatically correct
* hide AI involvement in projects or capstone work when disclosure is required

---

# Disclosure Expectations in This Course

For major work in this course, especially project and capstone work, students may be required to account for their AI use.

Students should be prepared to explain:

* what they were trying to build
* what AI was used for
* what AI produced
* what they accepted, changed, or rejected
* how they tested the result
* what decisions remained theirs

This course may use the [AI Use Justification Guide](D:\@Artifact_Generation\108_AAISE_Details\10-152-117_Python_Programming\AI_Use_Justification_Guide.md:1) for that purpose.

---

# Relationship to RBA

Later in the course, students are introduced to Refraction-Based Architecture in a bounded way.

This does not replace Python fundamentals.

Instead, it helps students understand a more deliberate way of framing, structuring, and governing AI-assisted project work.

In this course, AI use should increasingly move toward:

* clearer problem framing
* stronger structure before generation
* more deliberate revision and explanation

---

# Final Standard for This Course

In `10-152-117 Python Programming`, responsible AI use means:

* the student can still build and explain core Python logic
* the student uses AI as support rather than substitution
* the student validates, revises, and justifies the final result
