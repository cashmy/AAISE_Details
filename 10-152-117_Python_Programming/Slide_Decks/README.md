# Slide Decks

This folder contains slide-deck `.md` artifacts for `10-152-117 Python Programming`.

These artifacts are designed to support lecture delivery and slide creation.

They should be understood as:

* a structural guide
* a cognitive pacing guide
* a visual-anchor guide
* an instructional governance layer

They should **not** be treated as a rigid copy-and-paste lecture script.

---

# Important Use Guidance

The slide decks are:

* **canonical for structure**
* **flexible for delivery**

That means an instructor may reasonably:

* add a small exposure concept when it supports the session
* trim a slide or idea when the live session needs less
* rephrase an anchor line to fit delivery style
* emphasize one concept more strongly for a particular class section
* adapt examples while preserving the readiness target

Examples of acceptable light adaptation:

* adding a brief exposure reference such as `mutable vs immutable`
* strengthening a watch point if the class is confused
* simplifying a demo anchor for a less experienced section

The key is to preserve:

* the readiness target
* the primary watch point
* assignment alignment
* demo alignment
* the hands-on bridge
* the closing success definition

If those remain intact, the deck remains aligned even when the delivery varies slightly.

# Governance Chain

These slide decks are downstream of:

* `Lecture_Content_and_Demo_Alignment_Matrix.md`
* `Lecture_Outlines/`
* `STD-Py_Alignment_Based_Slide_Deck_Template.md`
* `Slide_Deck_System_Meta_Review.md`

The intended workflow is:

1. alignment artifact
2. lecture outline
3. slide deck
4. live instructional adaptation

If revision is needed, it is usually better to revise upstream first rather than only changing the slide layer.
