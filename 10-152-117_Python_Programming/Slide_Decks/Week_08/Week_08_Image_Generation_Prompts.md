# Week 8 Image Generation Prompts

**Course:** 10-152-117 Python Programming  
**Week:** Week 8 - Capstone Build, Justification, and Presentation

---

# Prompt Use Notes

Week 8 visuals should support final clarity, not add new complexity. Avoid
overproducing imagery for presentation days. Day 3 especially should use little
or no generated imagery unless a simple expectations slide is useful.

Avoid:

- legal/audit styling
- performance-stage anxiety
- robot-centered AI imagery
- complex project management boards
- dense code screenshots

---

# Week 8 Day 1 - Build Expectations And Validation Evidence

## Slide 1 - Finishing Code Is Not Enough

Create a clean comparison visual.

Left side:

- "Code runs once"
- small terminal output

Right side:

- "Code runs with evidence"
- terminal output plus validation note

Tone should be professional and calm.

Avoid:

- legal compliance imagery
- scary error screens
- cluttered IDE screenshots

## Slide 3 - Name The Behavior That Matters Most

Create a simple project-flow visual with one core behavior highlighted.

Labels:

- "project purpose"
- "core behavior"
- "evidence"

Make the core behavior visually central.

Avoid:

- many feature cards
- complex architecture
- dashboard UI

## Slide 4 - Evidence Can Be Small And Real

Create a three-card validation visual.

Cards:

- expected vs actual
- successful run
- boundary check

Add a small note:

- "Small evidence is still evidence."

Avoid:

- testing framework logos
- legal/audit appearance
- dense text

## Slide 5 - Run Instructions Are Part Of The Project

Create a clean project folder visual with a README card.

README sections:

- file to run
- data needed
- expected result

Keep it minimal and readable.

Avoid:

- actual file explorer screenshots
- cluttered folder trees
- package publishing imagery

## Slide 9 - A15 Build Checklist

Create a compact checklist titled "A15 Build Checklist".

Items:

- approved scope
- working core
- organized code
- validation evidence
- run instructions
- AI-use notes

Use classroom-friendly styling.

Avoid:

- audit stamps
- legal document style
- excessive icons

# Week 8 Day 2 - Optional Revision, Staging, And Presentation Readiness

## Slide 1 - Today May Not Need A Lecture

Create a three-mode session visual.

Modes:

- build support
- short reset
- presentations

Show the instructor choosing the mode that best fits the class needs.

Avoid:

- complex schedule grids
- clock-pressure imagery
- performance-stage visuals

## Slide 3 - Reality Contact Reveals Priorities

Create a visual showing an original project plan adjusted after a test run.

Labels:

- "original plan"
- "what the run revealed"
- "better final focus"

Tone should suggest learning and improvement.

Avoid:

- failure imagery
- red warning marks
- broken computer visuals

## Slide 5 - Record One Meaningful Revision

Create a simple revision note card with three fields:

- what changed
- why it changed
- how it improved the project

Use a clean notebook or README style.

Avoid:

- dense paragraphs
- legal/audit styling
- dramatic before/after imagery

## Slide 6 - Presentation Is Explanation

Create a presentation sequence visual with six steps:

- purpose
- main behavior
- code/structure
- validation
- revision
- AI use

Keep it calm and instructional, not stage-performance focused.

Avoid:

- auditorium stage imagery
- spotlight/performance anxiety
- excessive decoration

## Slide 9 - Move Into Final Work

Create a final-priority checklist visual.

Items:

- finish working core
- validate behavior
- complete run instructions
- prepare explanation
- present if scheduled

Avoid:

- compliance styling
- cluttered project boards
- red urgency colors

# Week 8 Day 3 - Final Presentations

## Slide 1 - Final Presentation Day

Create a calm classroom presentation visual showing a student project on a
screen and a simple checklist beside it.

Checklist:

- demonstrate
- explain
- validate
- account for AI

Avoid:

- stage spotlight
- nervous performance imagery
- corporate keynote styling

## Slide 2 - What To Explain

Create a simple six-item explanation checklist.

Items:

- purpose
- main behavior
- code or structure
- validation evidence
- revision or decision
- AI use, if applicable

Use large readable text and minimal icons.

Avoid:

- dense rubric tables
- legal/audit visuals
- decorative clutter

## Slide 3 - AI-Use Accountability

Create a four-step accountability flow:

- AI contributed
- I changed or rejected
- I verified
- I decided

The visual should show student ownership, not AI replacement.

Avoid:

- robot characters
- scary AI imagery
- implying AI is forbidden

## Slide 4 - Questions Are Part Of The Assessment

Create a calm Q&A visual with a student explaining a project and an instructor
asking a question.

Caption:

- "Questions verify understanding."

Tone should be supportive and professional.

Avoid:

- interrogation imagery
- courtroom visuals
- anxious body language
