# Week 8 Image Generation Prompts

**Course:** 10-152-117 Python Programming  
**Week:** Week 8 - Capstone Build, Justification, and Presentation

---

# Prompt Use Notes

Week 8 visuals should support final clarity, not add new complexity. Avoid
overproducing imagery for presentation days. Day 3 especially should use little
or no generated imagery unless a simple expectations slide is useful.

Avoid:

- legal/audit styling
- performance-stage anxiety
- robot-centered AI imagery
- complex project management boards
- dense code screenshots
- panic or deadline-pressure imagery

---

# Week 8 Day 1 - Build Expectations And Validation Evidence

## Slide 1 - Finishing Code Is Not Enough

Create a clean comparison visual.

Left side:

- "Code runs once"
- small terminal output

Right side:

- "Code runs with evidence"
- terminal output plus validation note

Tone should be professional and calm.

Avoid:

- legal compliance imagery
- scary error screens
- cluttered IDE screenshots

## Slide 2 - From Approved Scope To Build Evidence

Create a visual showing approved project scope flowing into build evidence.

Show three connected cards:

- "approved scope"
- "working behavior"
- "evidence and run guidance"

Keep it simple and final-week focused.

Avoid:

- paperwork-heavy approval imagery
- formal stamp graphics
- project-management clutter

## Slide 3 - Today's Success Pattern

Create a success-pattern visual for final capstone build work.

Show six steps:

1. "stay inside approved scope"
2. "identify core behavior"
3. "validate with real evidence"
4. "preserve run instructions"
5. "record AI help if used"
6. "prepare to explain"

Use a calm checklist or path layout.

Avoid:

- feature-sprawl imagery
- legal/compliance styling
- panic colors

## Slide 4 - Evidence Can Be Small And Real

Create a three-card validation visual.

Cards:

- expected vs actual
- successful run
- boundary check

Add a small note:

- "Small evidence is still evidence."

Avoid:

- testing framework logos
- legal/audit appearance
- dense text

## Slide 5 - Run Instructions Are Part Of The Project

Create a clean project folder visual with a README card.

README sections:

- file to run

- expected result

Keep it minimal and readable.

Avoid:

- actual file explorer screenshots
- cluttered folder trees
- package publishing imagery

## Slide 6 - AI Notes Belong With The Build

Create an AI-use note visual focused on student ownership.

- "AI suggested"

- "I can explain"

- robot mascots

## Slide 7 - Demo: Validation Evidence
