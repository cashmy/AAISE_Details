# SLIDE DECK - WEEK 8 DAY 1

* Course: 10-152-117 Python Programming
* Week / Day: Week 8 / Monday
* Date: October 5, 2026
* Weekly Theme: Capstone Build, Justification, and Presentation
* Lecture Title: Build Expectations and Validation Evidence
* Assignments Supported: A15 - Capstone Build
* Readiness Target: students can identify what part of their project matters most and how they will verify it
* Primary Watch Point: do not assume students know what "validation evidence" looks like unless modeled explicitly

---

### SLIDE 1 - OPENING FRAME

Finishing code
is not enough.

---
Cue:
- Open with quality and explainability, not urgency alone.
- Make it clear that validation is part of finishing well.

Visual:
- Layout: Contrast
- Content:
  - code that runs
  - code that runs with evidence
- Purpose:
  - position validation as part of project completion

### SLIDE 2 - COURSE POSITIONING

The project is approved.
Now it must be defensible.

---
Cue:
- Connect this session to the Week 7 approval process.
- Frame build week as implementation plus accountability.

Visual:
- Layout: Flow
- Content:
  - approved scope
  - build
  - validation evidence
- Purpose:
  - show what changes once build begins

### SLIDE 3 - CORE IDEA

Name the behavior
that matters most.

---
Cue:
- Push students to identify one or two meaningful behaviors first.
- Keep the target concrete and central to project value.

Visual:
- Layout: Isolated focus
- Content:
  - one key behavior statement
  - one project context label
- Purpose:
  - anchor validation to meaningful project behavior

### SLIDE 4 - CORE IDEA

Evidence can be small.
It still has to be real.

---
Cue:
- Normalize lightweight but intentional checks.
- Contrast real evidence with vague confidence.

Visual:
- Layout: Three-part panel
- Content:
  - expected vs actual
  - simple test case
  - run evidence
- Purpose:
  - broaden the student idea of what validation can look like

### SLIDE 5 - DEMO ANCHOR

---
Cue:

- Direct attention to how the evidence supports the claim.

Visual:
- Layout: Sequence
- Content:
  - project behavior
  - validation step

  - make proof and behavior visibly connected

### SLIDE 6 - THINKING TOOL

What matters most?
How will you prove it?

---
Cue:

Visual:

### SLIDE 7 - COMMON FAILURE

Validation gets skipped
when build momentum takes over.

---
Cue:
- Be direct here.
- Explain that “I’ll test later” often becomes no evidence at all.

Visual:
- Layout: Contrast
- Content:
  - uncontrolled build rush
  - bounded build with checks
- Purpose:
  - protect validation from being crowded out by implementation pressure

### SLIDE 8 - BRIDGE

---
Cue:

- Reinforce that evidence collection belongs inside the build, not after it.

Visual:
- Layout: Flow
- Content:
  - approved scope
  - build step
  - validation note
- Purpose:
  - connect the lecture directly to capstone work habits
