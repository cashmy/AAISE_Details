# SLIDE DECK - WEEK 1 DAY 1

* Course: 10-152-117 Python Programming
* Week / Day: Week 1 / Monday
* Date: August 17, 2026
* Weekly Theme: First Programs and Basic Values
* Lecture Title: What a Python Program Does
* Assignments Supported: A1 - First Programs
* Readiness Target: students can run a tiny program and explain what a variable stores
* Primary Watch Point: do not assume `input()` yet; keep setup friction from consuming the session

---

### SLIDE 1 - OPENING FRAME

Make something happen.
Then explain it.

---
Cue:
- Start with confidence, not complexity.
- Say explicitly that the goal is visible success, not impressive code.

Visual:
- Layout: Split contrast
- Content:
  - Left side: blank editor or empty screen
  - Right side: tiny Python output visible in terminal
- Purpose:
  - show that today's win is movement from nothing to visible result

### SLIDE 2 - COURSE POSITIONING

Start small.
Build outward.

---
Cue:
- Position the course as gradual and intentional.
- Lower anxiety by saying students are not expected to know everything yet.

Visual:
- Layout: Flow
- Content:
  - small block labeled "tiny programs"
  - arrow to larger block labeled "later projects"
- Purpose:
  - frame the whole course as cumulative rather than overwhelming

### SLIDE 3 - CORE IDEA

Programs follow instructions.
Line by line.

---
Cue:
- Keep this concrete and literal.
- Emphasize that Python is not guessing what we mean.

Visual:
- Layout: Stack
- Content:
  - three short code lines stacked vertically
  - subtle highlight showing top-to-bottom execution
- Purpose:
  - install the mental model that execution happens in sequence

### SLIDE 4 - CORE IDEA

`print()` makes work visible.

---
Cue:
- Treat `print()` as the first high-payoff tool.
- Reinforce that visible output is immediate evidence the program ran.

Visual:
- Layout: Before / After
- Content:
  - left: `print("Hello")`
  - right: terminal showing `Hello`
- Purpose:
  - connect code directly to visible output

### SLIDE 5 - CORE IDEA

Variables store values.
Not magic.

---
Cue:
- Slow down here.
- Explain that the variable is the label and the value is what is stored.

Visual:
- Layout: Split contrast
- Content:
  - left: label `student_name`
  - right: value `"Avery"`
- Purpose:
  - separate the name from the stored content clearly

### SLIDE 6 - DEMO ANCHOR

Watch the value move.

---
Cue:
- Introduce the demo by telling students exactly what to notice.
- Ask: what value is stored, and what line makes it visible?

Visual:
- Layout: Flow
- Content:
  - variable assignment
  - arrow
  - `print(variable)`
  - arrow
  - output in terminal
- Purpose:
  - focus student attention on value flow during the demo

### SLIDE 7 - COMMON FAILURE

Text needs quotes.

---
Cue:
- Preempt the most likely beginner mistake.
- Show that unquoted text is not interpreted the same way as a string.

Visual:
- Layout: Split contrast
- Content:
  - left: `"Hello"`
  - right: `Hello`
- Purpose:
  - install the rule before students hit the error repeatedly

### SLIDE 8 - BRIDGE

Run a tiny program.
Change one value.

---
Cue:
- Direct the lab goal very clearly.
- Tell students not to worry about `input()` or calculations yet.

Visual:
- Layout: Flow
- Content:
  - step 1: type a greeting
  - step 2: store text in a variable
  - step 3: change the value and rerun
- Purpose:
  - bridge from lecture into immediate hands-on action

### SLIDE 9 - CLOSING

If it runs and you can explain it,
you succeeded.

---
Cue:
- End with a success definition that reduces perfection pressure.
- Reinforce that explanation matters as much as visible output today.

Visual:
- Layout: Isolated focus
- Content:
  - one tiny successful program snippet
  - one short line of output
- Purpose:
  - anchor the first-day success condition in something small and achievable
