# SLIDE DECK - WEEK 3 DAY 3

* Course: 10-152-117 Python Programming
* Week / Day: Week 3 / Thursday
* Date: September 3, 2026
* Weekly Theme: Organizing Code and Data
* Lecture Title: Comparing Rough and Cleaner Program Structure
* Assignments Supported: A4 - Function Builder; A5 - List or Dictionary Mini-App
* Readiness Target: students can compare a rough solution to a cleaner organized one
* Primary Watch Point: bounded AI use depends on manual baseline existing first; do not invert that sequence

---

### SLIDE 1 - OPENING FRAME

Working code
can still improve.

---
Cue:
- Frame the day as judgment, not just execution.
- Emphasize that readability and manageability matter.

Visual:
- Layout: Split contrast
- Content:
  - rough version
  - cleaner version
- Purpose:
  - show that both versions may work, but not equally well

### SLIDE 2 - COURSE POSITIONING

This week built
logic and structure.

---
Cue:
- Connect functions and data structures to today’s comparison work.
- Position revision as the next step after getting something to run.

Visual:
- Layout: Flow
- Content:
  - functions
  - collections
  - arrow to comparison
- Purpose:
  - show how Week 3 parts combine into evaluation and improvement

### SLIDE 3 - CORE IDEA

Correct
is not the same as clear.

---
Cue:
- Say this slowly and plainly.
- Invite students to notice human readability, not just machine behavior.

Visual:
- Layout: Contrast
- Content:
  - “runs correctly”
  - “easy to read and revise”
- Purpose:
  - separate correctness from organization quality

### SLIDE 4 - CORE IDEA

Cleaner structure
is easier to explain.

---
Cue:
- Tie organization directly to the course emphasis on explanation.
- Ask students which version they would rather talk through.

Visual:
- Layout: Before / After
- Content:
  - vague names and repeated code
  - clearer names and grouped responsibilities
- Purpose:
  - show why organization improves explainability

### SLIDE 5 - DEMO ANCHOR

Watch what changed.
Then ask why.

---
Cue:
- Use before the rough-vs-cleaner comparison demo.
- Focus attention on specific changes, not general “better-looking” impressions.

Visual:
- Layout: Annotated comparison
- Content:
  - repeated code reduced
  - names improved
  - data layout clarified
- Purpose:
  - direct students to concrete evidence of improvement

### SLIDE 6 - THINKING TOOL

What got clearer?
What got easier?

---
Cue:
- Use these two questions as the evaluation heuristic.
- Keep judgment simple and repeatable.

Visual:
- Layout: Two-question panel
- Content:
  - clarity question
  - manageability question
- Purpose:
  - give students a usable reasoning tool for comparison

### SLIDE 7 - COMMON FAILURE

AI comes after
manual baseline.

---
Cue:
- Be explicit here.
- If the manual version is weak or missing, stay manual.

Visual:
- Layout: Ordered flow
- Content:
  - manual baseline
  - comparison
  - optional AI review
- Purpose:
  - protect bounded AI use and preserve learning sequence

### SLIDE 8 - BRIDGE

Revise one version.
Explain the improvement.

---
Cue:
- Bridge into revision, cleanup, and explanation practice.
- Keep the target on one meaningful improvement, not wholesale rebuilding.

Visual:
- Layout: Revision loop
- Content:
  - rough version
  - one improvement pass
  - explanation note
- Purpose:
  - connect comparison directly to the hands-on work

### SLIDE 9 - CLOSING

If you can justify
the improvement,
you understand it.

---
Cue:
- Close on explanation as evidence of judgment.
- Reinforce that students are learning to compare, not imitate blindly.

Visual:
- Layout: Isolated focus
- Content:
  - one revised example
  - one short justification line
- Purpose:
  - end the session on explainable improvement
