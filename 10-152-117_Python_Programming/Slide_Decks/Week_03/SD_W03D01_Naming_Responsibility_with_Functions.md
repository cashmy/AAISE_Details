# SLIDE DECK - WEEK 3 DAY 1

* Course: 10-152-117 Python Programming
* Week / Day: Week 3 / Monday
* Date: August 31, 2026
* Weekly Theme: Organizing Code and Data
* Lecture Title: Naming Responsibility with Functions
* Assignments Supported: A4 - Function Builder
* Readiness Target: students can explain what each function is responsible for
* Primary Watch Point: do not assume deep return-value fluency too fast; keep function count small and intentional

---

### SLIDE 1 - OPENING FRAME

Code can work
and still be messy.

---
Cue:
- Frame functions as an organization move, not a syntax stunt.
- Normalize that Week 3 is about shaping code, not making it more complicated.

Visual:
- Layout: Split contrast
- Content:
  - one long undivided code block
  - one shaped version with named parts
- Purpose:
  - show why organization matters before introducing structure details

### SLIDE 2 - COURSE POSITIONING

Last week: program flow.
This week: program shape.

---
Cue:
- Connect functions to work students already know how to do.
- Emphasize that functions help manage logic they already understand.

Visual:
- Layout: Flow
- Content:
  - variables
  - conditions
  - loops
  - arrow to functions
- Purpose:
  - show that functions organize existing skills rather than replace them

### SLIDE 3 - CORE IDEA

Repeated code
is a signal.

---
Cue:
- Teach the reason for refactoring before the keyword `def`.
- Ask students where they see repetition and why it becomes a problem.

Visual:
- Layout: Highlighted example
- Content:
  - short repeated snippet shown twice
  - repeated lines visually marked
- Purpose:
  - help students notice when organization is needed

### SLIDE 4 - CORE IDEA

A function owns
one clear job.

---
Cue:
- Keep responsibility language central.
- Ask: “What job does this function own?”

Visual:
- Layout: Isolated focus
- Content:
  - one function name
  - one brief purpose statement
- Purpose:
  - anchor the mental model of a function as a named responsibility

### SLIDE 5 - SYSTEM

Values come in.
Results come out.

---
Cue:
- Introduce parameters and return values as controlled data flow.
- Keep this simple and narrated, not abstract.

Visual:
- Layout: Flow
- Content:
  - parameter input
  - function box
  - return value output
- Purpose:
  - make function data flow visible at a beginner level

### SLIDE 6 - DEMO ANCHOR

Watch the code
become easier to explain.

---
Cue:

Visual:

### SLIDE 7 - COMMON FAILURE

More functions
is not better.

---
Cue:
- Preempt random splitting and over-structuring.
- Reinforce “small and intentional.”

Visual:
- Layout: Contrast
- Content:
  - left: one reasonable function split
  - right: overly fragmented version
- Purpose:
  - prevent students from equating quantity with quality

Visual:

you can shape the code.
