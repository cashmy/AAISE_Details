# Week 2 Image Generation Prompts

**10-152-117 Python Programming**

---

# Purpose

This companion artifact expands the Week 2 v2 deck source image notes into
more explicit image-generation prompts.

Use these prompts when PowerPoint Designer does not provide a useful visual or
when a slide needs a more precise instructional image.

These prompts should support, not replace, the slide text and instructor demo.

---

# Style Guidance For All Week 2 Images

Use a clean instructional style appropriate for beginner programming students.

Preferred visual qualities:

- simple diagrammatic layout
- readable labels
- high contrast
- light background
- restrained color
- one main idea per image
- no dense code walls
- no photorealistic classroom scenes unless intentionally selected later

Avoid:

- complex flowcharts
- advanced software architecture imagery
- abstract neon technology backgrounds
- intimidating warning visuals
- too many arrows or labels
- showing topics not used in the current slide

# Week 2 Day 1 - How Programs Make Decisions

Source deck:

`SD_W02D01_How_Programs_Make_Decisions_v2.md`

## Slide 1 - Programs Can Choose

Create a clean instructional diagram showing a simple Python program path that
runs straight down for Week 1, then splits into two possible paths for Week 2.
Label the first path "one path" and the split paths "path A" and "path B".
Include a small Python file icon at the start and two simple output boxes at
the end. Keep the image calm, beginner-friendly, and uncluttered.

Avoid complex flowcharts, app screens, or business-process diagrams.

## Slide 3 - Today's Success Pattern

Create a three-step horizontal flow diagram with the labels "condition checked",
"branch selected", and "output shown". Use simple arrows between the steps.
Add a small checkmark or spotlight on the active branch step. The visual should
make the sequence easy to remember.

Avoid tiny text, nested branches, or more than three major steps.

## Slide 4 - What We Will Use Today

Create a simple toolbox-style visual for beginner Python decision logic. The
toolbox should contain labeled cards for `True`, `False`, comparison symbols,
`if`, `elif`, `else`, and "branch prediction". Use clean icons or cards rather
than realistic tools.

Avoid adding loops, functions, files, or advanced Python topics.

## Slide 5 - What We Will Skip For Now

Create a "parked for later" visual with four labeled items placed in a side
area: loops, repeated input, pattern matching, and one-line conditionals. The
main area should show a single decision path labeled "today's focus".

Avoid making the deferred topics look forbidden, dangerous, or unimportant.

## Slide 6 - Conditions Ask Questions

Create a beginner-friendly visual showing the condition `score >= 70` inside a
question bubble. The bubble should split into two result cards labeled `True`
and `False`. Add a small caption: "A condition asks a yes/no question."

Avoid mathematical density or unnecessary formulas.

## Slide 7 - Comparison Operators

Create six clean operator cards arranged in a grid: `>`, `<`, `>=`, `<=`, `==`,
and `!=`. Under each card, include a very short plain-English meaning such as
"greater than" or "not equal". Keep text large enough for a slide.

Avoid making the visual look like an advanced math reference sheet.

## Slide 9 - The `if` Statement

Create a simple code-shape diagram for an `if` statement. Show a condition line
at the top and an indented block underneath. Use visual indentation, a bracket,
or a highlighted block to make it obvious which line belongs to the branch.

Avoid dense code and avoid including `elif` or `else` in this image.

## Slide 11 - Demo 2: Grade Check Branches

Create a branch-prediction visual for a grade checker. Show one score value
flowing into a vertical chain of grade branches. Highlight one selected path,
such as score 84 leading to "Grade: B". Dim the other branches.

Avoid too many score values or a full gradebook layout.

## Slide 13 - Common Failure: `=` Is Not `==`

Create a side-by-side comparison visual. Left panel: `score = 84` labeled
"store the value". Right panel: `score == 84` labeled "compare the value".
Use different colors for storage versus comparison while keeping the style
simple and readable.

Avoid error-message styling or anything that makes the topic feel punitive.

## Slide 14 - Common Failure: Indentation Changes Meaning

Create a visual showing an `if` condition with two indented lines grouped under
it and one unindented line below the group. Use a bracket or shaded region to
show "inside the branch" versus "after the branch".

Avoid long code examples.

## Slide 15 - Assignment 2 Bridge

Create four small assignment-option cards for a decision program: grade
checker, eligibility checker, weather message, and simple recommendation.
Each card should show a tiny condition arrow leading to output.

Avoid making one option appear required or more important than the others.

## Slide 16 - Evidence For A Decision Program

Create a lightweight evidence visual showing one `.py` file, two small test
value cards, visible output, and a short explanation note. The labels should
be readable and beginner-friendly.

Avoid large documentation binders or professional QA dashboards.

# Week 2 Day 2 - Repetition With Control

Source deck:

`SD_W02D02_Repetition_with_Control_v2.md`

## Slide 1 - Repeat On Purpose

Create a simple visual of an action repeated several times with a clear stop
marker at the end. Use a sequence of repeated blocks or footprints ending at a
sign labeled "stop". The image should communicate controlled repetition.

Avoid endless spirals or visuals that imply the loop never stops.

## Slide 2 - Logic Chooses, Loops Repeat

Create a two-column comparison diagram. Left column: "branches choose" with a
simple split path. Right column: "loops repeat" with a small circular arrow
that returns to the repeated action. Keep both sides visually balanced.

Avoid complex control-flow diagrams.

## Slide 3 - Today's Success Pattern

Create a three-part loop cycle labeled "repeat action", "update or advance",
and "check stopping point". Use a circular flow, but keep it spacious and easy
to read.

Avoid nested arrows or adding extra steps.

## Slide 4 - What We Will Use Today

Create a toolbox visual for loop concepts with labeled cards: `for`, `range()`,
counter, accumulator, `while`, and stopping condition. Use a clean classroom
diagram style.

Avoid including nested loops, generators, or advanced iterator language.

## Slide 5 - What We Will Skip For Now

Create a "save for later" shelf with nested loops, advanced iterators,
generators, and large menus placed on the shelf. 

Avoid making the saved topics look like errors.

## Slide 6 - Ask What Repeats

Create a small code-block illustration where the repeated action is highlighted
inside a loop body. The repeated action can be represented as "print number"
or "add value". Include a label: "this part repeats".

Avoid full code walls.

## Slide 7 - Ask What Changes

Create a visual showing a value changing across loop passes: pass 1, pass 2,
pass 3. Use a simple counter or total increasing. Include arrows between the
passes and a label "state changes".

Avoid charts that look like data analytics.

## Slide 8 - Ask What Stops It

Create a loop cycle with an exit path. The cycle should include a condition
check and a clear exit marker labeled "stop when condition is false" or "range
is finished". Keep it friendly and not alarmist.

Avoid warning signs or error-heavy imagery.

## Slide 10 - Demo 1: Counting With `for`

Create a visual showing `range(5)` stepping through values 0, 1, 2, 3, 4 and
printing one output line for each value. Use a simple left-to-right sequence.

Avoid explaining zero-based counting in too much detail on the image.

## Slide 12 - Demo 2: Accumulator Loop

Create a small table-style visual with columns "pass", "number", "old total",
and "new total". Show three rows with simple values. Highlight the new total
column to show the accumulated result.

Avoid a full spreadsheet look.

## Slide 15 - Demo 3: `while` Countdown

Create a countdown loop visual showing current value 3, then 2, then 1, then
stop. Highlight the update step that subtracts 1 each time. Include a condition
label such as "while count > 0".

Avoid showing an infinite loop or frightening error state.

## Slide 17 - Assignment 3 Bridge

Create small cards for loop assignment options: counting program, total
accumulator, number sequence, and practice loop. Each card should show a simple
repeat arrow and a stop marker.

Avoid making a menu loop appear required.

## Slide 18 - Closing Success Check

Create a checklist visual for loop evidence: first pass, what changes, stop
point, visible output. Use checkboxes and a small loop icon.

Avoid long written explanations.

# Week 2 Day 3 - Combining Logic And Repetition

Source deck:

`SD_W02D03_Combining_Logic_and_Repetition_v2.md`

## Slide 1 - Choose And Repeat

Create a clean diagram showing a branch icon and a loop icon combining into a
small Python program file. Label the branch "choose" and the loop "repeat".
The final file should be labeled "small program".

Avoid large app or dashboard imagery.

## Slide 2 - Monday Plus Tuesday

Create a two-column recap visual. Left column: Monday with a branch diagram and
the phrase "conditions choose". Right column: Tuesday with a loop diagram and
the phrase "loops repeat". Add a small arrow at the bottom pointing to
"Thursday: combine carefully".

Avoid dense text.

## Slide 3 - Today's Success Pattern

Create a path diagram with the labels "input or value", "condition", "branch
or loop", "update", and "output". Use one highlighted route through the path.
Keep it readable and not overly technical.

Avoid complex state-machine diagrams.

## Slide 4 - What We Will Use Today

Create a toolbox visual with labeled cards for conditions inside loops, loops
controlled by conditions, simple validation, menu-style logic, test values, and
visible output.

Avoid data structures, files, classes, or APIs.

## Slide 5 - What We Will Skip For Now

Create a clean instructional slide visual titled "Parked For Later".

Show a calm "save for later" area, like a simple shelf, parking area, or holding zone with four labeled cards:

- nested loops
- many menu options
- multiple features
- advanced input handling

The visual should communicate: these ideas are useful, but they are not today's focus.

Use muted blue and gray colors with a small clock or bookmark icon to suggest "later".

Add a short bottom caption:
"Useful ideas, saved until the main path is clear."

Style:
Simple vector-style educational diagram, light background, readable labels, spacious layout, no app dashboard, no web UI, no login screen, no charts, no database icons, no warning signs, no clutter.

## Slide 7 - Validation Is Logic Plus Repetition

Create a validation-loop diagram. Show "ask for value", then "check value",
then a repeat arrow for "not acceptable", and an exit arrow for "acceptable".
Use simple labels and clear arrows.

Avoid password/security imagery.

## Slide 8 - Demo 1: Input Loop With Exit

Create a repeated prompt visual where user input cycles through a loop until an
exit value is entered. Highlight the exit condition and the final stop path.

Avoid showing many different input values.

## Slide 9 - Menu Logic Is A Pattern

Create a small menu-pattern diagram with four steps: show options, get choice,
use branch, repeat or exit. Use simple cards or icons for each step.

Avoid a realistic app menu with many buttons.

## Slide 10 - Demo 2: Menu With Conditionals

Create a visual showing a user choice flowing to one matching branch, with
another path for exit. Use only three menu options plus exit, and highlight one
selected branch.

Avoid too many menu items.

## Slide 11 - Trace The Whole Path

Create a highlighted route through a combined logic diagram. Include labels:
starting value, condition checked, branch selected, loop update, final output.
The path should be one clear route, not all possible routes.

Avoid full code.

## Slide 12 - Test More Than One Path

Create four small test cards labeled branch A, branch B, repeat more than once,
and stop condition. Each card should have a small checkmark or output icon.

Avoid formal unit-testing framework imagery.

## Slide 13 - Common Failure: Too Much At Once

Create a split visual. Left side: small traceable program with one condition
and one loop. Right side: cluttered mini-application with many unlabeled
features. Use the left side as the preferred path.

Avoid making the right side look humorous or insulting.

## Slide 14 - Common Failure: Hidden Stop Logic

Create a loop cycle with the stop condition spotlighted. Add a label "Can this
condition actually become false?" Use a clear exit path.

Avoid warning-heavy red visuals.

## Slide 17 - Evidence For Week 2

Create an evidence layout showing two `.py` files, small output samples, and
two short explanation notes: one for decision logic and one for loop stopping
logic. Keep the layout light and organized.

Avoid large portfolio or capstone imagery.

## Slide 18 - Closing Success Check

Create a traceability checklist from value to output: starting value, condition,
branch, repeat, change, stop, output. Use a simple vertical checklist with a
small path line beside it.

Avoid too much text or tiny labels.
