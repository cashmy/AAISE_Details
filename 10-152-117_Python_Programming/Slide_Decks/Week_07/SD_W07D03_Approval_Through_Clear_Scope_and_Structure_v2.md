## Slide 1 - Approval Is About Fit

**Delivery Category:** Core

**Student-Visible Text:**

Approval is not about whether an idea sounds exciting.

Approval asks whether the project fits the course, the time available, the
student's current skills, and the need for clear explanation.

**Instructor Notes:**

Set a calm review tone. Approval is quality control.

**Transition Cue:**

Connect approval back to yesterday's scope work: fit is a build decision, not
just an idea decision.

## Slide 6 - Approval Criteria

**Delivery Category:** Core

**Student-Visible Text:**

An approvable proposal shows:

- clear purpose
- realistic features
- expected inputs and outputs
- likely structure
- risks or unknowns
- AI-use plan
- why the scope is realistic

**Instructor Notes:**

This mirrors A14 and gives students a checklist before review.

**Transition Cue:**

Once criteria are visible, compare possible project paths by risk and fit.

## Slide 8 - Can This Be Finished?

**Delivery Category:** Core

**Student-Visible Text:**

Ask:

- What is the smallest working version?
- What can be tested first?
- What can be removed if time gets tight?
- What must be true for this to count as working?

**Instructor Notes:**

This converts proposal approval into an A15 build plan.

**Transition Cue:**

Finishability is not enough; the project also needs to be explainable.

---

## Slide 9 - Can This Be Explained?

**Delivery Category:** Core

**Student-Visible Text:**

Ask:

- Can I describe the main logic?
- Can I explain the data?
- Can I show validation evidence?
- Can I explain AI contributions, if any?

**Instructor Notes:**

This ties A15 and A16 together.

**Transition Cue:**

If the answer to any of those questions is weak, revision is the next useful
move.

## Slide 10 - Revision Is Not Rejection

**Delivery Category:** Core

**Student-Visible Text:**

Targeted revision protects the student from building something too large,
unclear, or hard to explain.

**Instructor Notes:**

This reduces defensiveness during approval conversations.

**Transition Cue:**

Now inspect an approval-ready proposal example against the criteria.

# AI-Use Boundary

AI may help with:

- project structure comparison
- risk identification
- first-build planning
- debugging after the student has attempted implementation

AI must not:

- expand beyond approved scope
- generate unexplained code
- replace validation
- replace the student's final explanation
