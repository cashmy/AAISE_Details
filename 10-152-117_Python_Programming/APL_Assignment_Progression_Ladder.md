# ASSIGNMENT PROGRESSION LADDER (APL) — Python Programming

---

# Purpose

This artifact defines the assignment progression for `10-152-117 Python Programming`.

Unlike the HTML/CSS/JS course, this course is not built around one semester-long evolving project through the full term.

Instead, this assignment system uses:

* short, targeted, individual assignments
* occasional two-session scaffolds when a concept benefits from extension
* recurring problem domains only when they help reinforce learning
* a final capstone as the main point of integration

This structure fits the compressed timeline, broader topic spread, and stronger need for isolated concept practice before full project integration.

---

# Assignment Philosophy

This ladder is designed around five principles:

## 1. Early assignments should be small and winnable

Students need visible success quickly. Early assignments should feel achievable and should reinforce the idea that they can make Python programs work and explain what they are doing.

## 2. Concepts should be isolated before they are integrated

Students learn foundational Python more effectively when variables, logic, loops, functions, collections, files, and APIs are first practiced in bounded contexts.

## 3. Reuse problem domains only when it supports scaffolding

The course may revisit small themes such as trackers, menus, lookups, or data retrieval, but assignments should not be forced into one continuous artifact.

## 4. AI use should scale with student readiness

Assignments should reflect the course AI progression:

* manual-first early
* bounded comparison or debugging support in the middle
* more deliberate and accountable AI use later

## 5. Integration belongs primarily in the capstone

The capstone is the place where students combine concepts, use bounded RBA framing, and justify AI use. Earlier assignments prepare them for that moment.

# Assignment Sequence

## Assignment 1 — First Programs

**Primary Focus:**

* output
* variables
* strings
* basic numeric values
* input/output flow

**Likely Scope:**

* one session

**Description:**

Students build 2-3 very small Python programs that accept simple input and produce useful output. Examples may include a greeting program, a simple cost calculator, or a personalized message builder.

**Instructional Purpose:**

This assignment establishes the idea that Python is something students can use immediately. It should reward accuracy, clarity, and explanation rather than complexity.

**AI Allowance:**

* none for normal student work

**Capstone Preparation Value:**

* builds confidence
* reinforces tracing values through a program

---

## Assignment 2 — Decisions in Code

**Primary Focus:**

* booleans
* comparisons
* `if` / `elif` / `else`

**Likely Scope:**

* one session

**Description:**

Students create a small decision-based program such as a grading check, discount checker, eligibility screener, or recommendation tool.

**Instructional Purpose:**

This assignment helps students understand that programs can choose between outcomes based on logic. It should remain small enough that every branch can still be traced and explained.

**AI Allowance:**

* none for normal student work

**Capstone Preparation Value:**

* builds logical reasoning
* supports later validation and debugging habits

---

## Assignment 3 — Loops and Repetition

**Primary Focus:**

* `for`
* `while`
* repetition
* stopping conditions

**Likely Scope:**

* one session

**Description:**

Students build a repetition-focused program such as a counting tool, repeated-input collector, or simple loop-driven menu.

**Instructional Purpose:**

This assignment helps students reason about repeated behavior and identify how loops begin, continue, and stop. It should surface common mistakes such as infinite loops or missing updates.

**AI Allowance:**

* none for normal student work

**Capstone Preparation Value:**

* supports input handling and repetitive workflows used later in mini-apps

---

## Assignment 4 — Function Builder

**Primary Focus:**

* functions
* parameters
* return values
* refactoring repeated code

**Likely Scope:**

* one session, possibly extending into a second if needed

**Description:**

Students refactor earlier logic into functions and build a small program where different pieces of logic are broken into named parts.

**Instructional Purpose:**

This assignment introduces the idea that code can be organized intentionally. The point is not only correctness, but clearer structure and responsibility.

**AI Allowance:**

* limited comparison allowed after a manual baseline exists

**Capstone Preparation Value:**

* supports readable structure
* prepares students for comparing organizational strategies

---

## Assignment 5 — List or Dictionary Mini-App

**Primary Focus:**

* lists
* dictionaries
* storing and retrieving data
* iteration over collections

**Likely Scope:**

* one to two sessions

**Description:**

Students build a small structured mini-app using a collection-based problem domain, such as a score tracker, item lookup, menu selector, or simple task list.

**Instructional Purpose:**

This assignment gives students practice managing program state in a more realistic way. It should feel like a small tool rather than an isolated syntax drill.

**AI Allowance:**

* limited comparison or revision after the student has a manual version

**Capstone Preparation Value:**

* introduces simple state management
* supports later file persistence and structured project work

---

## Assignment 6 — Debug and Explain

**Primary Focus:**

* debugging
* tracing
* testing
* explanation

**Likely Scope:**

* one session

**Description:**

Students receive intentionally broken code and must identify problems, repair them, and explain both the bug and the fix. Some examples may include function-based code, loop logic, or collection handling.

**Instructional Purpose:**

This assignment reinforces that ownership includes diagnosis, correction, and explanation. It also creates a natural place to compare manual debugging with bounded AI debugging support.

**AI Allowance:**

* bounded debugging assistance only after manual diagnosis is attempted

**Capstone Preparation Value:**

* directly supports capstone troubleshooting and explanation

---

## Assignment 7 — Reading Structured Code

**Primary Focus:**

* code literacy
* class recognition
* class vs function structure comparison

**Likely Scope:**

* one session

**Description:**

Students inspect, explain, and lightly modify a simple class-based program, then compare it with a procedural or function-based version of the same basic task.

**Instructional Purpose:**

This assignment strengthens students' ability to interpret and govern AI-generated code that may default to classes. The goal is recognition and modification, not deep OOP theory.

**AI Allowance:**

* explanation support allowed in a bounded way

**Capstone Preparation Value:**

* prepares students to evaluate AI-generated structure choices

---

## Assignment 8 — Save and Load Utility

**Primary Focus:**

* file input/output
* persistence
* text or JSON storage
* basic error handling

**Likely Scope:**

* one to two sessions

**Description:**

Students build a small program that stores information and retrieves it later. This may extend a familiar domain such as a task list, note keeper, or tracker.

**Instructional Purpose:**

This assignment helps students feel that their programs can now persist data. It also introduces more realistic failure handling.

**AI Allowance:**

* bounded support for alternate file-handling or error-handling approaches after manual work begins

**Capstone Preparation Value:**

* supports projects that need saved state or stored information

---

## Assignment 9 — Structured Data Reader

**Primary Focus:**

* CSV or JSON interpretation
* structured data access
* simple transformation of data into useful output

**Likely Scope:**

* one session

**Description:**

Students read a provided CSV or JSON file and produce a meaningful summary, filtered result, or simple report.

**Instructional Purpose:**

This assignment helps students understand that structured data can be inspected, extracted, and reshaped, which is important for both files and API responses.

**AI Allowance:**

* bounded comparison of parsing approaches

**Capstone Preparation Value:**

* prepares students for later external-data work

---

## Assignment 10 — API Data Fetcher

**Primary Focus:**

* APIs
* requests and responses
* JSON parsing
* external data use

**Likely Scope:**

* one to two sessions

**Description:**

Students retrieve data from a simple API or controlled endpoint and display selected information in a useful way. Examples could include weather, public information, or other approved low-complexity sources.

**Instructional Purpose:**

This assignment makes Python feel connected to the outside world. It also creates a natural place for students to compare manual code with bounded AI-assisted code and to discuss validation.

**AI Allowance:**

* bounded implementation support allowed

**Capstone Preparation Value:**

* supports later projects that use external data or API integration

---

## Assignment 11 — RBA Project Framing Exercise

**Primary Focus:**

* project intent
* constraints
* structure choice
* bounded AI planning

**Likely Scope:**

* one session

**Description:**

Students frame a small project idea before coding by identifying purpose, inputs, outputs, constraints, likely structure, and where AI might or might not help.

**Instructional Purpose:**

This assignment serves as a bridge into the capstone. It is less about implementation and more about helping students think more deliberately before building.

**AI Allowance:**

* bounded support only after the student frames the problem manually

**Capstone Preparation Value:**

* directly supports capstone approval and scoping

---

## Assignment 12 — Capstone Proposal and Approval

**Primary Focus:**

* project scope
* feasibility
* structure
* AI use boundaries

**Likely Scope:**

* one session plus instructor review

**Description:**

Students submit a capstone proposal for approval. The proposal should describe the project goal, likely features, program structure, risks, data use if any, and expected AI involvement.

**Instructional Purpose:**

This assignment keeps capstone scope realistic and creates a checkpoint before students commit to a project path.

**AI Allowance:**

* bounded and disclosed

**Capstone Preparation Value:**

* establishes the approved project path

---

## Assignment 13 — Capstone Build

**Primary Focus:**

* integrated Python development
* implementation
* debugging
* revision
* bounded RBA application

**Likely Scope:**

* two sessions

**Description:**

Students build the approved capstone project using concepts from across the course. Projects may vary, but all must remain explainable, testable, and scoped appropriately.

**Instructional Purpose:**

This is the primary integration assignment of the course. Students move from targeted concept practice into a more complete project experience.

**AI Allowance:**

* strategic use allowed with accountability

**Capstone Preparation Value:**

* this is the capstone itself in progress

---

## Assignment 14 — AI Use Justification and Final Presentation

**Primary Focus:**

* explanation
* authorship
* AI accountability
* presentation

**Likely Scope:**

* one session

**Description:**

Students present the final capstone and submit a brief AI use justification explaining what they built, how AI was used, what they changed or rejected, how they tested the result, and what decisions remained theirs.

**Instructional Purpose:**

This final assignment ensures that the course evaluates understanding, judgment, and ownership, not just visible functionality.

**AI Allowance:**

* full disclosure required

**Capstone Preparation Value:**

* demonstrates completion, explanation, and accountability

# Final Design Rationale

This ladder is intentionally different from the HTML/CSS/JS course.

The HTML/CSS/JS course benefits from one evolving project because the medium naturally supports visible iterative accumulation across the semester.

This Python course benefits more from:

* focused concept practice
* short builds
* limited scaffolds
* late integration

That makes the capstone more meaningful because students arrive with a wider set of practiced skills rather than a single project they have been dragging forward across every topic.
