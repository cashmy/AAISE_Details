# ASSIGNMENT 2 — DECISIONS IN CODE

**Week 2 — Decision Logic and Repetition**

---

# Context

Programs become more useful when they can make decisions.

In this assignment, you will write a small program that chooses between different outcomes based on conditions.

The focus is on clear logic, not complexity.

---

# Objective

Create a Python program that uses conditionals to make decisions.

Your program should demonstrate:

* boolean expressions
* comparisons
* `if`, `elif`, and/or `else`
* clear output based on program logic

---

# Task

Build one small decision-based program.

Possible options include:

* grade checker
* discount checker
* eligibility checker
* simple recommendation tool
* temperature or weather-message program
* login-style rule checker using sample values

Your instructor may assign one option or approve your choice.

---

# Requirements

Your program should:

* use at least one `if` statement
* use a comparison such as `>`, `<`, `>=`, `<=`, `==`, or `!=`
* produce different output for different conditions
* use readable variable names
* run without syntax errors

If appropriate, your program may use `elif` and `else` to handle multiple outcomes.

---

# AI Use

AI is not allowed for normal work on this assignment unless the instructor explicitly says otherwise.

You should practice writing and tracing conditional logic manually.

---

# Submission Requirements

Submit your `.py` file as instructed.

Your submission should include:

* one working Python file
* clear variable names
* visible output
* logic that can be tested with more than one value or scenario

---

# Reflection / Explanation

Answer briefly:

> What condition does your program check, and what different outcomes can happen?

# Success Criteria

To succeed on this assignment:

* your program should make a clear decision
* your conditions should match the intended outcomes
* your output should make sense
* you should be able to explain why each branch runs

---

# Instructor Notes

Keep this assignment small enough that every branch can be traced.

Students may confuse assignment `=` with comparison `==`; use this as a debugging and explanation opportunity.

The key learning target is:

> condition is checked → branch is selected → output reflects the decision
