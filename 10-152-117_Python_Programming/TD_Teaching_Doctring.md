# 📘 Teaching Doctrine (TD-01)

### *Python Programming (Basics) — AI-Augmented Learning Model*

---

# 🔹 Core Principle

> **Students learn programming by thinking, building, and evaluating—using AI as a tool, not a substitute.**

---

# 🔹 Instructional Model (Non-Negotiable)

Every learning cycle follows:

> **Think → Build → Evaluate → Adapt**

---

### 🔹 Phase Breakdown

#### 1. Think (Human First)

* Student:

  * describes the problem
  * outlines approach
* No AI allowed

👉 Purpose:

* prevents blind generation
* builds ownership

---

#### 2. Build (Manual + AI)

* Student:

  * writes code manually
  * uses AI to assist or extend

👉 Purpose:

* reduces frustration
* accelerates progress

---

#### 3. Evaluate (Critical Layer)

* Student:

  * checks correctness
  * explains code
  * identifies issues

👉 Purpose:

* prevents “vibe-coding”
* builds understanding

---

#### 4. Adapt (Real-World Layer)

* Student:

  * modifies approach
  * explains solution without AI

👉 Purpose:

* builds independence
* prepares for real environments

---

# 🔹 AI Usage Model (Explicit)

AI is:

### ✅ Allowed

### ✅ Encouraged

### ❌ Not authoritative

---

## 🔹 Rule of Engagement

> **“AI must be given your thinking first.”**

---

## 🔹 Acceptable Use

* generating starter code
* suggesting improvements
* debugging assistance

---

## 🔹 Unacceptable Use

* copying without understanding
* skipping problem framing
* submitting unverified code

---

# 🔹 Week 1 Meta-Frame (Critical Delivery)

This is not optional. This is where you prevent failure.

---

## 🟦 Opening Message to Students (Core Idea)

You should explicitly tell them:

---

> “This course will feel different from how you may have learned before.
>
> You will not just be writing code—you will be learning how to think about problems, how to build solutions, and how to use AI tools effectively.
>
> You are allowed to use AI. In fact, you are expected to.
>
> But you are also expected to understand what you build.
>
> This course is designed so that you can:
>
> * write code
> * understand code
> * fix code
> * and explain code
>
> You do not need to be perfect.
> You do need to think.”

---

👉 This reduces:

* anxiety
* confusion
* resistance

---

# 🔹 Week 1 — AI Primer (Light, Practical)

---

## Topics (High-Level)

* What AI is (simple explanation)
* Types:

  * predictive (autocomplete)
  * generative (code/text)
* Strengths:

  * speed
  * structure
* Limitations:

  * can be wrong
  * lacks context

---

## Key Message

> “AI is fast—but not always right.”

---

## Quick Exercise

* Ask AI to generate code
* Run it
* Find something wrong or unclear

👉 Immediate grounding

---

# 🔹 Confidence Strategy (Critical)

You identified this correctly:

> If they don’t feel capable, we lose them.

---

## 🔹 Design Response

### 1. Early Wins (Week 1–2)

* simple programs
* visible outputs
* quick success

---

### 2. AI as Safety Net

* reduces frustration
* prevents “I’m stuck” moments

---

### 3. Repetition of Patterns

* loops appear often
* conditionals appear often
* same structures, different problems

---

### 4. Tangible Outputs

* small apps
* simple chatbot
* file-based tools

---

👉 Students must feel:

> “I built something real”

---

# 🔹 Cognitive Load Management

---

## 🔹 What You DO Teach

* patterns
* logic
* structure

---

## 🔹 What You DO NOT Overload

* deep theory
* edge-case syntax
* exhaustive coverage

---

👉 Rule:

> **Clarity over completeness**

---

# 🔹 Instructor Role (Very Important)

You are not:

* code debugger
* syntax enforcer

You are:

> **confidence builder + thinking coach**

---

## 🔹 Your Core Questions

Use these constantly:

* “What are you trying to do?”
* “How does this work?”
* “What would you try next?”

---

## 🔹 When a Student is Stuck

DO NOT:

* fix it for them

DO:

* guide thinking
* ask questions
* suggest AI use appropriately

---

# 🔹 Failure Mode Prevention

---

## 🚩 Pattern 1 — AI Copying

Fix:

* require explanation

---

## 🚩 Pattern 2 — Syntax Panic

Fix:

* normalize errors
* show debugging process

---

## 🚩 Pattern 3 — Overwhelm

Fix:

* simplify problem
* reduce scope

---

## 🚩 Pattern 4 — Passive Learning

Fix:

* require active input
* enforce Think phase

---
