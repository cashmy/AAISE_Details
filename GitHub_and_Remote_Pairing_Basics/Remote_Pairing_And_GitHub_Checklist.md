# Remote Pairing And GitHub Checklist

Use this checklist during Zoom pair/group work.

## Before Coding

- Confirm the assignment or lab.
- Decide roles:
  - driver
  - navigator
  - checker, if there are three people
- Open the current GitHub repository or downloaded project folder.
- Confirm everyone knows which files are current.
- Identify the first small goal.
- Agree when to switch roles.

## During Coding

- Driver shares screen and says changes out loud.
- Navigator watches logic and requirements.
- Checker watches requirements, tests, and notes questions.
- Keep the assignment instructions nearby.
- Test after small changes.
- Do not stack many untested edits.
- Ask questions early.

Useful phrases:

- "What should happen next?"
- "Can you explain that line?"
- "Let's test before changing more."
- "Which requirement does this meet?"
- "Can we name this more clearly?"

## GitHub At The Start

- Open the correct repository.
- Download the current version if needed.
- Extract the ZIP before editing.
- Open the extracted folder in the editor.
- Confirm partners are looking at the same current files.

## GitHub At The End

- Save all files.
- Test the page or program.
- Upload the updated files.
- Use a short commit message that says what changed.
- Confirm the updated files appear in GitHub.
- Send or submit the correct GitHub link as instructed.

## Avoid Overwriting

- Do not both edit separate copies and upload over each other.
- Ask before replacing files.
- Download the latest version before continuing later.
- Keep a backup if unsure.
- Pause and ask for help if versions are confusing.

## AI During Pair Work

If AI is allowed for the assignment:

- both partners should read the AI response
- both partners should discuss the response
- both partners should understand any code used
- both partners should test the result

Useful boundary:

```text
Do not rewrite it for us.
Explain the issue and ask one question before suggesting code.
```

## Before Ending The Session

- Roles were rotated or intentionally shared.
- The current version is in GitHub.
- Both partners can access the current version.
- Both partners can explain what changed.
- Remaining questions are written down.
