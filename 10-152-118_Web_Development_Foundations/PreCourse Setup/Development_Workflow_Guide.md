# **Development Workflow Guide — VS Code & GitHub**

---

## **Overview**

In this course, you will use:

* **Visual Studio Code (VS Code)** as your development environment
* **GitHub** to store and manage your project

These tools will help you:

* organize your work
* track changes over time
* safely make improvements
* recover from mistakes

---

## **Important Note**

> This is not a Git course.
> You are expected to learn and use a **simple, repeatable workflow**, not advanced Git features.

---

You must complete the following:

---

# 🧱 **Weekly Workflow (Repeat Every Week)**

This is your **standard process**.

---

## 🔹 Step 1 — Create a Weekly Branch

Each week, create a new branch:

```bash
git checkout -b week01-html
```

Example naming:

* `week01-html`
* `week02-css`
* `week03-layout`
* `week04-js`

---

## 🔹 Step 2 — Work on Your Assignment

* Open project in VS Code
* Make changes for your assignment
* Save your work frequently

---

## 🔹 Step 3 — Commit Your Work

After Iteration 1 (Tuesday):

```bash
git add .
git commit -m "Week 1 - Iteration 1"
```

After Iteration 2 (Thursday):

```bash
git add .
git commit -m "Week 1 - Iteration 2"
```

---

## 🔹 Step 4 — Push to GitHub

```bash
git push origin week01-html
```

---

## 🔹 Step 5 — Submit Your Work

Submit in Schoology:

* your GitHub repository link
* OR your branch link (if required)

---

# 🔁 **Weekly Pattern Summary**

```plaintext
Create Branch → Work → Commit → Refine → Commit → Push → Submit
```

---

# 🧠 **What This Workflow Gives You**

* a clean history of your work
* ability to go back to earlier versions
* separation between weekly assignments
* proof of progress and effort

---

# ⚠️ **Common Mistakes to Avoid**

---

## ❌ Not creating a branch

→ everything ends up mixed together

---

## ❌ Forgetting to commit

→ no record of your progress

---

## ❌ Working only locally

→ nothing saved to GitHub

---

## ❌ Overcomplicating Git

→ keep it simple

---

# 🔑 **Rules to Follow**

* Always create a new branch each week
* Commit at least twice (Iteration 1 & 2)
* Push your work before submission
* Keep your project organized

---
