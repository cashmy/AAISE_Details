# **Git Quick Reference — VS Code Version**

---

## 🧭 **Core Idea**

> Make changes → Save → Commit → Push

---

# 🧱 **Weekly Workflow (Always Follow This)**

```plaintext
Create Branch → Work → Commit → Refine → Commit → Push
```

---

# 🔹 **1. Create a New Branch (Start of Week)**

### In VS Code:

1. Look at the **bottom-left corner**
2. Click the current branch name (usually `main`)
3. Select **“Create new branch”**
4. Name it:

```plaintext
week01-html
```

✔ Keeps your work organized
✔ One branch per week

---

# 🔹 **2. Make Your Changes**

* Open your files
* Edit your code
* Save your work

✔ Changes will automatically appear in Source Control

---

# 🔹 **3. Open Source Control Panel**

* Click the **Source Control icon** (left sidebar)

  * looks like a branching symbol

You will see:

* list of changed files
* changes highlighted

---

# 🔹 **4. Stage Your Changes**

### Option A (Recommended):

* Click the **“+”** next to each file

### Option B:

* Click **“Stage All Changes”**

✔ Prepares files for commit

---

# 🔹 **5. Commit Your Work**

1. Enter a message at the top:

```plaintext
Week 1 - Iteration 1
```

2. Click **✔ Commit**

✔ Saves your progress

---

# 🔹 **6. Push to GitHub**

* Click **“Sync Changes”** OR **“Push”**

✔ Sends your work to GitHub
✔ Required before submission

---

# 🔁 **Typical Weekly Pattern**

* Tuesday:

  * Commit → *Iteration 1*

* Thursday:

  * Commit → *Iteration 2*

* End of Week:

  * Push → Submit

---

# 🧠 **What the UI Means**

| VS Code Action | What It Does            |
| -------------- | ----------------------- |
| Changes list   | Files you modified      |
| “+” (Stage)    | Prepare file for commit |
| Commit ✔       | Save your progress      |
| Push / Sync    | Upload to GitHub        |

---

# ⚠️ **Common Problems & Fixes**

---

## ❌ Changes not showing in GitHub

✔ You forgot to click:

* **Push / Sync Changes**

---

## ❌ “No changes to commit”

✔ You may need to:

* save your file first
* or stage your changes

---

## ❌ On the wrong branch

✔ Click branch name (bottom-left)
✔ Switch to correct branch

---

## ❌ Files look messy or confusing

✔ Use Source Control panel
✔ Review changes before committing

---

# 🔑 **Rules to Follow**

* Create a new branch each week
* Commit at least twice (Iteration 1 & 2)
* Push before submitting
* Keep commit messages simple

---

# 🧭 **Branch Naming Pattern**

```plaintext
week01-html
week02-css
week03-layout
week04-js
```

---

# 🧠 **Pro Tip**

> If something looks wrong, open the Source Control panel—it shows exactly what changed.

# 🔑 **Final Thought**

> You are not expected to master Git—just follow the workflow.
