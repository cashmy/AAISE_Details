# Week 15 Guide - Capstone Proposal And Scope

**Course:** 10-152-118 Web Development Foundations  
**Purpose:** Prepare for the capstone by proposing a right-sized web project that uses course concepts clearly and can be completed, refined, and explained.

---

## 1. What The Proposal Is For

The capstone proposal is not a promise to build a perfect final product.

It is a plan for a project that is:

- appropriate for your current skill level
- connected to the course concepts
- possible to complete within the remaining time
- clear enough for your instructor to approve or help adjust
- something you can explain at the end of the course

Useful mental model:

```text
The proposal defines the target.
The capstone build creates evidence that you can reach that target.
The final presentation explains what you built and why.
```

---

## 2. PageForge As An Instructor Example

Your instructor may use `PageForge` as a demonstration project.

`PageForge` shows how a project can grow over time:

- start with structure
- add styling
- add layout
- add interaction
- use data and state
- improve performance, safety, and usability
- refine the final result

Your capstone does not need to be as complex as `PageForge`.

You are not expected to copy `PageForge`.

Instead, use it as an example of the process:

```text
Start simple.
Build steadily.
Refine intentionally.
Explain your choices.
```

## 4. Project Identity

Give your project a clear identity.

Answer:

```text
Project name:

One-sentence description:

Intended user or audience:

Main purpose:
```

Example:

```text
Project name: StudySprint
One-sentence description: A simple study planner for tracking assignments and focus sessions.
Intended user or audience: Students who want a lightweight way to organize weekly work.
Main purpose: Help users add tasks, view priorities, and track progress.
```

The project identity should help someone quickly understand what you are
building.

---

## 5. Core Purpose

The core purpose is what your project helps the user do.

Try to write it as a user-centered statement:

```text
This project helps users ___ so they can ___.
```

Examples:

```text
This project helps users organize recipes so they can find meal ideas quickly.
```

```text
This project helps users view local event information so they can decide what to attend.
```

```text
This project helps users track project tasks so they can see what still needs work.
```

If the purpose is unclear, the project may become too scattered.

## 6. Required Project Layers

Your capstone should show evidence of the major layers from the course.

Describe how your project will use each layer.

### HTML Structure

```text
What pages, sections, headings, navigation, or content areas will your project need?
```

### CSS Styling And Layout

```text
How will the project use styling, layout, spacing, color, typography, and responsiveness?
```

### JavaScript Interaction

```text
What will the user click, type, select, add, remove, filter, show, hide, or update?
```

### Forms Or Input

```text
What form, input, or user-submitted information will the project use?
```

### Data Or State

```text
What information does the project need to display, remember, update, or organize?
```

### Refinement

```text
How will you improve performance, safety, usability, or visual clarity?
```

Not every project needs every possible feature, but the project should clearly
show meaningful use of the course layers.

## 7. Required Features

List the features your project must include for the capstone to feel complete.

Keep this list realistic.

Required features:

```text
1.
2.
3.
4.
```

Good required features are specific and achievable.

Example:

```text
1. A home page with navigation and project introduction.
2. A form that lets the user add a task.
3. A task list that updates when tasks are added.
4. A visual status or progress area that reflects the current task state.
```

---

## 8. Optional Or Stretch Features

Stretch features are allowed, but they should not be required for the project to
succeed.

Optional features:

```text
1.
2.
3.
```

Examples:

- theme toggle
- saved preference
- filter or search
- extra page
- animation polish
- API data
- simulated login

Beginner rule:

```text
If the project fails without this feature, it is required.
If the project still works without it, it is optional.
```

---

## 9. Out Of Scope

A strong proposal says what the project will not do.

This protects the project from becoming too large.

Out of scope:

```text
1.
2.
3.
```

Examples:

- real user accounts
- real payment processing
- real password storage
- backend database
- public hosting
- multi-user collaboration
- advanced animation system
- full e-commerce checkout

Naming what is out of scope is not a weakness. It is a sign of good planning.

---

## 10. Simulated Login Disclosure, If Used

If your project includes login-like behavior, describe it accurately.

Use wording like:

```text
This project includes a simulated login interface for practicing form validation
and logged-in/logged-out UI states.
```

Do not claim:

```text
This project has secure authentication.
```

Unless you are using real server-side authentication, your login-like feature is
a front-end simulation.

Do not store real passwords, real tokens, API keys, or private account
information in your front-end code or browser storage.

## 12. Explanation Plan

At the end of the course, you should be able to explain your project.

Prepare to explain:

- what your project does
- who it is for
- how HTML, CSS, and JavaScript work together
- what user interaction you built
- what data or state your project uses
- what you refined or improved
- what problem you solved while debugging
- what you would improve with more time
- how you used AI assistance, if applicable

Use this pattern:

```text
I built ___ for ___.
It helps users ___.
The main interaction is ___.
The most important technical part is ___.
One improvement I made was ___ because ___.
```

---

## 13. Approval Checklist

Before approval, check whether your proposal is:

- clear enough to understand
- connected to an approved project track or approved custom idea
- achievable within the course timeline
- not too large
- not too small
- able to show HTML, CSS, and JavaScript
- able to include meaningful interaction
- able to include form/input, data, or state in a reasonable way
- safe and honest about simulated login or sensitive data
- something you can demonstrate and explain

Your instructor may approve the proposal, ask you to narrow it, or ask you to
clarify specific parts before you continue.
