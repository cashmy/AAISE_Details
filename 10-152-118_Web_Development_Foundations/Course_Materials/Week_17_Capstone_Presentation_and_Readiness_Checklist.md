# Week 17 Guide - Capstone Presentation And Readiness Checklist

## Purpose

The final capstone presentation is your opportunity to demonstrate what you built and explain how it works.

A finished project is not only something that runs. You should also be able to explain your structure, styling, behavior, decisions, testing, and revision process.

## Presentation Structure

Use this sequence to prepare a clear 5-7 minute presentation.

### 1. What I Built

Explain:

* project name
* one-sentence purpose
* intended user or audience

### 2. Why I Chose It

Explain:

* the problem, need, or idea behind the project
* why the scope was realistic for this course
* what you intentionally left out

### 3. Demonstration

Show the project working.

During the demo, walk through:

* the main page or pages
* the most important user actions
* any form, input, button, navigation, data display, or state change
* the feature that best represents your work

### 4. How It Works

Explain the project in web development terms.

Include the parts that apply:

* HTML: how the page structure supports the content and interface
* CSS: how layout, spacing, color, and responsive behavior are handled
* JavaScript: what behavior, events, functions, data, or state control the project
* JSON or API data: what data is used and how it is read or displayed
* localStorage or state: what information changes and whether anything persists

### 5. What Course Concepts It Uses

Choose 2-4 important concepts from the course.

Examples:

* semantic HTML
* layout and responsive design
* forms and input
* DOM interaction
* events
* functions
* state
* JSON
* API request or simulated data
* browser security awareness
* performance or UX refinement
* debugging and testing

### 6. Challenge And Solution

Describe one meaningful challenge.

Explain:

* what did not work at first
* how you diagnosed the issue
* what you changed
* how you knew the fix worked

### 7. AI Use, If Applicable

If you used AI, briefly explain:

* what AI helped with
* what you accepted, changed, or rejected
* how you verified the result
* what decisions remained yours

Use the Week 17 AI Use Explanation Guide for more detail.

### 8. What I Would Improve Next

Name one or two realistic next steps.

Examples:

* improve the visual design
* add another page or feature
* strengthen validation
* improve mobile layout
* use a real API
* organize files more cleanly
* add better error messages or empty states

## Final Readiness Checklist

Before presentation day, confirm:

* the project opens correctly
* links and navigation work
* images and assets load
* the main features can be demonstrated
* form/input behavior works as expected
* the browser console has no unexpected errors
* the page is readable on a smaller screen
* the project files are organized and named clearly
* you know which file contains the main HTML, CSS, and JavaScript
* you have a short demo path planned
* you can explain at least one challenge and solution
* you can explain any AI use if applicable

## Backup Plan

Technology sometimes fails during presentations.

Prepare a simple backup:

* know where your project files are located
* keep your project ready to open in the browser
* consider having one or two screenshots available
* know the main points you can explain even if a live demo has trouble

The goal is not perfection. The goal is to show ownership and understanding.

## Explanation Checklist

You should be able to answer questions like:

* What is the purpose of this project?
* Which files are the most important?
* What part of the HTML gives the page structure?
* What part of the CSS controls layout or responsive behavior?
* What part of the JavaScript controls the main interaction?
* Where does data or state appear in the project?
* What did you test?
* What did you revise?
* What would you improve next?
* If AI was used, what did it contribute and what decisions remained yours?

## Final Reminder

The presentation is not only a product showcase.

It is evidence that you can build, test, revise, and explain a web project using the course concepts.
