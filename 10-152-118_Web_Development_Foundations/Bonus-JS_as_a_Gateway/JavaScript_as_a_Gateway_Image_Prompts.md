# JavaScript as a Gateway - Image Prompts

## Prompting Approach

These prompts are drafted before image generation so the instructional target can be reviewed before any image model attempts realization.

Each image should function as a teaching visual, not decoration. The visual should help students understand categories, relationships, sequence, or learning paths in the JavaScript ecosystem.

General constraints for all images:

- Use a clean educational infographic style suitable for a college web development course.
- Use legible, simple labels only.
- Avoid tiny text, dense paragraphs, brand logos, mascots, decorative code rain, glowing abstract backgrounds, or fake screenshots.
- Do not use actual company logos; use text labels and simple neutral icons instead.
- Keep composition clear enough for both article reading and slide use.
- Prefer a professional instructional palette with balanced contrast and multiple color families.
- Avoid one-note purple/blue gradients or purely decorative visual effects.
- Make the realization target explicit: the image must communicate the concept named in the prompt.

Realization-target controls:

- Treat each prompt as a request for a specific instructional diagram, not a general illustration about JavaScript.
- Before generating, identify the concrete realized object: map, layer stack, timeline, orbit map, component diagram, progression, comparison chart, or learning path map.
- The finished image should pass the stated success check for that prompt.
- If the image model struggles with exact text, prioritize the correct diagram structure and keep labels short; text can be corrected later in the article or slide layer.
- Do not substitute a decorative technology collage for a structured teaching visual.

## Image 1 - JavaScript Ecosystem Map

Use case: infographic-diagram
Asset type: article figure and opening slide visual
Realization target: A category map where JavaScript visibly connects course foundations to ecosystem categories.
Primary request: Create a clean educational ecosystem map showing how JavaScript connects the Web Foundations course to the larger modern frontend ecosystem.
Scene/backdrop: Light, neutral classroom handout background with subtle grid or paper texture.
Subject: JavaScript as the central gateway from HTML/CSS/JS foundations into professional web development categories.
Style/medium: Polished educational infographic, flat vector-like illustration, clear labels, no logos.
Composition/framing: Landscape 16:9. Place "HTML + CSS + JavaScript" on the left as the starting foundation. Place "JavaScript" near the center as the gateway. Branch outward to labeled regions: "Languages", "Frameworks", "Metaframeworks", "Runtimes", "Tooling", "Component UI", "Design Systems", "Learning Paths".
Text (verbatim): "JavaScript as a Gateway", "HTML", "CSS", "JavaScript", "Languages", "Frameworks", "Metaframeworks", "Runtimes", "Tooling", "Component UI", "Design Systems", "Learning Paths"
Constraints: The image must read as a map of categories, not as a checklist of every tool. Use simple arrows or paths. Keep labels large and few.
Success check: A student should be able to say, "JavaScript is the gateway from HTML/CSS/JS into several professional web development categories."
Avoid: Company logos, tiny tool-name clutter, fake UI screenshots, decorative code background, excessive neon, dense paragraphs.

## Review Notes

Before generation, review for:

- Does each prompt clearly define the instructional target?
- Is each visual distinct enough to avoid repetition?
- Are all required labels short enough for reliable image rendering?
- Are the prompts over-reliant on in-image text?
- Should any image be created manually as SVG/HTML instead of generated as raster?
- Should any prompt be split into article and slide variants?
- Does the realized image match the requested object type, or did it drift into a decorative technology illustration?
- Can the artifact be judged against the success check without relying on the image model's internal claim of completion?
