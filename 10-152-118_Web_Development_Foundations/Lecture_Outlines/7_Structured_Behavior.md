# 🧭 **WEEK 7 — MONDAY LECTURE OUTLINE**

**Title:** *Week 7 — Structured JavaScript: From Working to Clear*

---

## **1. Opening Frame**

> “Up to this point, your code has been focused on working.
> This week, we focus on making it understandable.”

* Introduce idea of **code quality**
* Not perfection—clarity

---

## **2. Course Positioning**

> “You now know how to write JavaScript and debug it.
> Now we improve how it is written.”

* connects directly to Week 4 (logic) and Week 6 (debugging)

---

## **3. Core Concepts**

* Code organization:

  * grouping related logic
* Functions as structure:

  * reusable pieces
* Naming variables clearly
* Reducing duplication
* Basic code readability

---

## **4. Demonstration / Example Layer**

* Show:

  * messy code vs clean code
* Show:

  * repeated logic → function
* Show:

  * unclear names vs clear names

👉 Emphasize:

* readability improves debugging

---

## **5. Common Mistakes / Watch-Fors**

* writing everything in one block
* unclear variable names (`x`, `data`, etc.)
* repeated code
* trying to over-engineer

---

## **6. Tuesday Lab Bridge**

> “In lab, your goal is not to add new features.
> Your goal is to improve what you already have.”

Focus:

* refactor existing code
* organize logic
* improve naming

---

## **7. Closing Frame**

> “If someone else can understand your code, you’re improving.”

---

# 🧭 **WEEK 7 — WEDNESDAY CONCEPT FOCUS**

**Title:** *Week 7 — Readability and Maintainability*

---

## **1. Re-Anchor the Week**

> “This week is about writing code that is easier to work with.”

---

## **2. Deep Concept Focus**

* Code is read more than written
* Structure reduces cognitive load
* Clear code reduces bugs
* Organization supports growth

---

## **3. Common Confusion Patterns**

* “It works, why change it?” → misunderstanding long-term impact
* “Refactoring breaks things” → lack of controlled change
* “I don’t know how to organize this” → lack of structure patterns

---

## **4. Thinking Tools / Heuristics**

* “Can I explain what this code does quickly?”
* “Is anything repeated?”
* “Are names meaningful?”
* “Would someone else understand this?”

---

## **5. Thursday Refinement Bridge**

> “For Thursday, focus on making your code easier to read and modify.”

Examples:

* break logic into functions
* rename variables
* simplify flow

---

## **6. Closing Reinforcement**

> “Clear code is easier to fix, extend, and trust.”

---
