# **Instructor Justification Brief (IJB-01)**

**HTML, CSS & JavaScript — Integrated Systems Instruction Model**

---

## **1. Purpose of This Approach**

This course preserves standard academic competencies while refining instructional delivery to better reflect how modern web systems are actually built and understood.

Web development is inherently multi-layered. HTML defines structure, CSS defines presentation, and JavaScript defines behavior. While these technologies are distinct, they operate together at runtime. Students who learn them in isolation often struggle when required to combine them into working systems.

This course addresses that gap by introducing technologies separately for clarity, and then progressively integrating them in controlled stages. The result is improved student understanding, stronger debugging ability, and better alignment with real-world development practices.

---

## **2. Instructional Model Overview**

Traditional instructional models often present web technologies in isolated blocks:

* HTML → CSS → JavaScript (sequential, siloed)

This course maintains the distinction between technologies but organizes learning around system behavior:

* **Structure → Style → Behavior → Systems → Integration**

Technologies remain distinct, but are taught as interacting layers within a system.

Students first learn each layer independently, then experience how those layers interact through guided and applied work. Integration is introduced progressively, not immediately, to avoid cognitive overload.

---

## **3. Preservation of Academic Standards**

This model does not alter the required academic structure.

* All **WIDS competencies are preserved** 
* Instructional content continues to cover:

  * HTML structure
  * CSS styling and layout
  * JavaScript interactivity
  * Debugging techniques
  * Structured development practices

Assessment remains:

* Criterion-based
* Observable
* Repeatable
* Aligned with defined learning outcomes

**Instruction is integrated; assessment remains structured and aligned.**

---

## **4. Assessment Model**

Student work is evaluated using a standardized rubric (MRS-02) aligned directly to competencies and institutional expectations.

Each assignment:

* Evaluates multiple competencies simultaneously
* Uses consistent scoring criteria
* Emphasizes observable outcomes rather than inferred understanding

A supporting Assignment Mapping Matrix (AMM-01) ensures that:

* Each competency is assessed multiple times
* Complexity increases over time
* Coverage is complete and defensible

In addition to technical competencies, the course integrates institutional Core Abilities , including:

* Problem solving
* Communication
* Productivity
* Learning agility
* Collaboration (pair programming)
* Professional behavior (remote engagement and presentation)

These are assessed through observable behaviors embedded in normal course activities, not through separate or additional grading structures.

**Each competency is assessed multiple times across increasing levels of complexity using consistent criteria.**

---

## **5. Cognitive Design Rationale**

The instructional sequence is intentionally staged to support learning progression:

1. **Foundational Phase (Weeks 1–3)**

   * Clear separation of HTML and CSS
   * Low cognitive load
   * Focus on structure and presentation

2. **Behavior Phase (Weeks 4–7)**

   * Introduction of JavaScript as a separate system
   * Controlled integration via DOM interaction
   * Emphasis on debugging as a core skill

3. **Systems Phase (Weeks 8–11)**

   * Introduction of data, asynchronous behavior, and state
   * Students begin working with full system interactions

4. **Integrity Phase (Weeks 12–15)**

   * Performance, security, and usability refinement
   * Focus shifts from building to improving systems

5. **Capstone Phase (Weeks 16–17)**

   * Independent application
   * Explanation and demonstration of understanding

Integration is introduced after foundational understanding, not before.

---

## **6. Role of Tools and AI**

Students progress through three stages of tooling:

1. **Native (Manual Implementation)**

   * Core concepts learned without assistance

2. **Assisted (AI and Debugging Support)**

   * AI used for explanation, refinement, and troubleshooting

3. **Library (Abstraction and Acceleration)**

   * Tools such as Bootstrap or Axios introduced only after foundational understanding

This progression ensures that students understand underlying mechanisms before using abstractions.

**Tools accelerate understanding—they do not replace it.**

---

## **7. Alignment with Workforce Expectations**

The course is designed to reflect modern development practices:

* **Pair programming** (Agile model)
* **Iterative development and debugging**
* **Working across multiple system layers**
* **Use of external tools and APIs**
* **Remote collaboration and communication**

Students are evaluated not only on what they build, but how they work:

* Participation in collaborative problem-solving
* Ability to explain technical decisions
* Professional engagement in remote environments
* Completion of tasks within structured workflows

These behaviors align directly with employer expectations and institutional Core Abilities .

**The course reflects how developers actually work: collaboratively, iteratively, and across multiple layers of a system.**

---

## **8. Implementation Guidance**

For instructors adopting this model:

* Follow the weekly progression as designed
* Maintain clear distinction between technologies in early phases
* Introduce integration gradually
* Use the standardized rubric consistently
* Emphasize functionality over perfection
* Evaluate observable behavior rather than inferred intent
* Introduce tools only after manual understanding is established

This model does not require additional grading overhead. It reorganizes instructional delivery while preserving existing assessment structures.

---

## **Conclusion**

This instructional model maintains traditional academic structure while aligning teaching more closely with how modern web systems are built, understood, and maintained.

It preserves:

* Defined competencies
* Measurable outcomes
* Institutional expectations

While improving:

* Student comprehension
* Debugging capability
* System-level thinking
* Workforce readiness

The result is a course that remains academically sound, operationally practical, and professionally relevant.

---

## **Summary Statement**

> This model maintains traditional academic structure while aligning instruction more closely with how modern web systems are built, understood, and maintained.
