# Bridge Replacement and New Course Candidates v1

## Purpose

This document identifies first-pass replacement and new-course candidates for
the AI-injected bridge version of the current Southwest Tech IT Software
Developer program.

It builds on the current bridge direction and course-direction artifacts,
especially the growing conclusion that several existing slots are now weaker
fits for the bridge:

- `10-152-123` SQL Programming Advanced
- `10-152-125` ASP.NET Programming (merged into C#)
- `10-152-130` Software Career Experience
- `10-152-133` Enterprise Data Systems & API Architecture

This is not a final recommendation set.

Its purpose is to identify the strongest candidate uses for newly available
curricular space.

---

## Design Logic

The bridge should not replace legacy courses simply to appear more modern.

Replacement should occur only when the new course or reallocated slot improves
one or more of the following:

- bridge coherence
- workforce-model alignment
- employability
- transition readiness toward AAISE
- curricular efficiency

This means the best candidates are not necessarily the most novel ones.

They are the ones that solve the clearest design problems.

---

## Freed or Weakening Slots

The current bridge conversation suggests that four areas create replacement
opportunity.

### Slot 1. `10-152-123` SQL Programming Advanced

This slot appears increasingly weak if it remains a second traditional
SQL-centered course.

The bridge direction now points toward:

- database modeling first
- relational and non-relational reasoning
- SQL as implementation and validation layer
- less emphasis on an additional SQL-heavy course

### Slot 2. `10-152-125` ASP.NET Programming

If ASP.NET exposure is merged into `10-152-122 C# Programming`, this frees a
full slot while preserving regional WM1 employability.

That makes this one of the most strategically useful openings in the bridge.

### Slot 3. `10-152-130` Software Career Experience

This slot appears too loose and too long in its current form.

A replacement here is likely one of the highest-value redesign decisions
available because it sits near the end of the program and can strongly shape
the bridge's professional identity.

### Slot 4. `10-152-133` Enterprise Data Systems & API Architecture

This slot appears increasingly redundant or over-scoped for the bridge if data,
REST, API, async, and integration concepts are introduced earlier and more
intelligently across the program.

## Strong Candidate Areas

### Candidate Area 1. Modern Data Modeling for AI-Enabled Systems

This is one of the strongest replacement candidates overall.

It would likely fit best in the space created by reducing or removing
`10-152-123 SQL Programming Advanced`.

A course or major module in this area could include:

- relational modeling
- document and graph models
- NoSQL patterns
- vector/embedding-aware storage concepts
- ORM and abstraction tradeoffs
- retrieval and context implications for AI-supported systems
- choosing the right data shape for the problem

This is strong because it improves both bridge and successor alignment without
requiring deep AI-native specialization too early.

### Candidate Area 2. Collaborative Delivery, GitHub, and CI/CD

This is another very strong bridge candidate.

It could exist as:

- a new course
- a major expansion of Agile Practices
- or a hybrid solution split across team workflow and project delivery

Core topics could include:

- Git and GitHub workflow
- branching and pull requests
- issue management
- code review
- actions and CI/CD pipelines
- deployment discipline
- AI-assisted development inside governed delivery workflow

This is one of the clearest employability gains available for the bridge.

### Candidate Area 3. Applied AI Integration Studio

This would be a stronger replacement for `Software Career Experience` than a
long, vague capstone.

The key idea would be a bounded, build-focused final experience in which
students integrate:

- software foundations
- AI-assisted workflow
- AI-injected architecture choices
- data/API interaction
- testing and justification

This could function as:

- a shorter capstone model
- a studio course
- a simulation-based applied build course
- or a more structured internship alternative

This feels stronger than the current course because it asks for demonstrated
integration rather than time spent in a loosely defined experience.

### Candidate Area 4. Systems Performance and AI Runtime Foundations

This area becomes strong if the current `10-152-128 C++ Programming` slot is
retained but radically reframed.

The strongest rationale is not simply keeping C++.

It is using the C++ slot to teach what the rest of the bridge does not expose
as directly:

- memory behavior
- performance tradeoffs
- abstraction boundaries
- lower-level systems thinking
- runtime awareness for AI-enabled software

This could also include selective advanced exposure to:

- LibTorch as a lower-level AI runtime perspective
- TensorFlow as ecosystem awareness

This should still remain a bounded bridge course, not a sprawling systems-plus-
everything course.

### Candidate Area 5. Flutter/Dart Mobile and Intelligent App Delivery

This is a more conditional candidate.

It becomes strong only if the bridge wants to preserve a mobile/application
delivery lane while making it more coherent than the current generic mobile
course.

Possible focus areas:

- Flutter/Dart foundations
- cross-platform application delivery
- mobile UI and state handling
- API-connected app behavior
- AI-assisted development workflow
- AI-aware or AI-enabled application patterns on mobile

This is viable, but probably lower priority than data modeling, delivery
workflow, and applied integration.

### Candidate Area 6. Secure AI-Enabled Systems

This is a secondary but meaningful candidate area if `10-151-101 Introduction
to Security` is eventually reconsidered.

Rather than introductory cyber awareness alone, a stronger bridge-aligned
security course could emphasize:

- secure software habits
- API and auth awareness
- data handling discipline
- AI-related privacy and governance concerns
- misuse and failure modes in AI-enabled systems

This looks stronger as a future refinement than as the immediate highest-value
replacement, but it should remain on the table.

## Best Candidate Mapping by Freed Slot

### If `10-152-123` is removed

Best fit candidates:

- Modern Data Modeling for AI-Enabled Systems
- or distributed redesign across SQL foundations plus advanced Python/data work

This looks like the clearest replacement logic.

### If `10-152-125` is merged into `10-152-122`

Best fit candidates:

- Collaborative Delivery, GitHub, and CI/CD
- or Applied AI Integration Studio

This slot is highly valuable because it sits in a space that can strengthen
professional workflow identity.

### If `10-152-130` is replaced

Best fit candidates:

- Applied AI Integration Studio
- structured internship/practicum hybrid
- or a bounded applied systems build course

This slot should probably become one of the bridge's clearest signature
experiences.

### If `10-152-133` is removed

Best fit candidates:

- Collaborative Delivery, GitHub, and CI/CD
- deeper cloud/integration work distributed elsewhere
- or a focused advanced applied systems course rather than a broad enterprise
  course

This slot should likely not be replaced by another over-scoped architecture
course unless the bridge later proves a real need for it.

---

## Priority Ranking

If prioritizing only the strongest current candidates, the order appears to be:

### Tier 1

- Modern Data Modeling for AI-Enabled Systems
- Collaborative Delivery, GitHub, and CI/CD
- Applied AI Integration Studio

### Tier 2

- Systems Performance and AI Runtime Foundations
- Flutter/Dart Mobile and Intelligent App Delivery

### Tier 3

- Secure AI-Enabled Systems

This ranking could change later, but it reflects current bridge needs fairly
well.

---

## Working Replacement Position

At the current stage, the bridge appears to benefit most from using freed
curricular space to strengthen:

- modern data-system reasoning
- professional development workflow
- bounded applied AI integration
- selected deeper technical systems or AI-runtime capability where justified

This is more coherent than preserving legacy-heavy courses that overlap too much
or no longer carry enough unique value.

---

## Next Questions

The next design-stage questions likely include:

- Which of the Tier 1 replacements should definitely become full bridge courses?
- Which should become full courses versus embedded cross-course modules?
- Should Applied AI Integration Studio replace `10-152-130` directly?
- Should `10-152-128` be formally redefined as a systems/performance/runtime
  course, and if so, how much LibTorch or TensorFlow exposure belongs there?
