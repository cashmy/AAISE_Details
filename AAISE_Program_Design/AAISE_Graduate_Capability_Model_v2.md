# AAISE Graduate Capability Model v2

## Purpose

This document provides a revised graduate capability model for the proposed
AAISE (Associates AI Software Engineering) direction and its AI-injected bridge
pathway.

It updates the earlier capability model based on what surfaced during:

- bridge-course redesign work
- current curriculum gap analysis
- bridge transition modeling
- replacement-course definition work

It does not define final courses.

Its purpose is to clarify what capabilities now appear necessary for graduates
if the program is to reflect the mixed software reality emerging across
conventional, AI-assisted, AI-injected, and AI-embedded work.

---

## Why a Revision Was Needed

The earlier capability model was directionally strong, but later bridge work
made several capabilities more explicit.

In particular, the design process surfaced stronger need for:

- governed AI-role selection
- AI-use justification
- collaborative delivery workflow
- modern data modeling across multiple paradigms
- systems-performance and abstraction awareness
- applied integration capability

These were partially implied before, but they now appear important enough to be
named more directly.

---

## Core Design Assumption

AAISE-aligned graduates should not be prepared for only one software reality.

They should be prepared to work across multiple Workforce Models:

- Native
- AI-Assisted
- AI-Injected
- AI-Embedded

This means graduates should leave not only with technical familiarity, but with
judgment about how to move between these environments responsibly.

---

## Capability Group 1. Software Foundations

Graduates should demonstrate durable software engineering fundamentals that
remain valuable with or without AI involvement.

This includes the ability to:

- frame problems before jumping to solutions
- reason through logic, flow, and program behavior
- write, read, and revise code with purpose
- debug and improve software methodically
- work with data structures, control flow, and core algorithmic logic
- communicate technical intent clearly

These capabilities remain foundational because AI does not remove the need for
judgment, diagnosis, or structured thinking.

---

## Capability Group 2. Governed AI-Assisted Development Practice

Graduates should be able to use AI as a development support mechanism without
becoming dependent on uncritical tool output.

This includes the ability to:

- use AI for coding, debugging, drafting, documentation, research, and analysis
- refine prompts, context, and constraints to improve results
- compare AI-generated options rather than accept the first plausible answer
- detect when AI output is shallow, misleading, or overconfident
- maintain authorship responsibility for final work

This group is broader than tool familiarity.

The deeper capability is governed AI use.

---

## Capability Group 3. AI Role Selection and Justification

Graduates should understand that AI can play different roles in software work
and that those roles should be chosen intentionally rather than passively.

This includes the ability to:

- distinguish between AI as explainer, assistant, and collaborator
- decide when one role is more appropriate than another
- explain why AI was used in a given task or project
- identify where AI should not be used
- justify accepted outputs in relation to evidence, fit, and constraints

This capability is important because mature AI use is not only about output.

It is also about judgment and justification.

---

## Capability Group 4. AI-Injected Application Design

Graduates should be able to participate in the design and implementation of
applications that incorporate AI capabilities intentionally rather than
superficially.

This includes the ability to:

- identify when AI is and is not an appropriate addition to a system
- define the intended role of AI within an application or workflow
- distinguish between a shallow AI feature and meaningful AI-enabled design
- reason about boundaries, fallback behavior, and failure modes
- design supporting flows for retrieval, transformation, validation, and review
- recognize that AI injection changes architecture, testing, and support needs

This moves beyond using AI as a helper and toward building systems in which AI
becomes part of the designed behavior.

---

## Capability Group 5. AI-Embedded Systems Awareness

Graduates should understand the role of AI inside business systems, workflows,
and data environments where AI becomes part of operational logic.

This includes the ability to:

- understand descriptive, predictive, and generative or transformative AI use
  in practical contexts
- reason about internal AI-supported workflows rather than only public-facing
  features
- identify governance, privacy, reliability, and oversight concerns
- understand the difference between a demo feature and an operationally useful
  AI-enabled business process

This does not require every graduate to be an advanced ML specialist.

It does require enough architectural and operational understanding to work in
environments where AI participates in how the system functions internally.

---

## Capability Group 6. Modern Data Modeling and Retrieval Reasoning

Graduates should understand how data shape, storage, abstraction, and retrieval
choices affect software and AI-enabled system behavior.

This includes the ability to:

- reason about relational and non-relational data models
- understand when different data approaches fit different problems
- recognize what ORMs and abstractions hide and reveal
- work with structured and semi-structured data thoughtfully
- understand why vector and embedding-oriented patterns matter in some AI
  contexts
- connect data modeling choices to downstream retrieval and application quality

This capability became more explicit through bridge design work and is now a
core part of the emerging data spine.

---

## Capability Group 7. Architectural and Systems Thinking

Graduates should be able to think beyond isolated code tasks and reason about
systems, structure, and consequences.

This includes the ability to:

- define what a system is trying to achieve before selecting implementation
  details
- identify components, boundaries, dependencies, and flows
- distinguish between symptoms and underlying causes
- evaluate tradeoffs rather than default to convenience
- understand how design decisions affect maintainability and change
- reason upward from implementation issues to architectural implications

This group remains essential because tool fluency alone does not create
coherence.

---

## Capability Group 8. Systems Performance and Abstraction Awareness

Graduates should understand that software abstractions carry hidden runtime
costs and tradeoffs.

This includes the ability to:

- reason about memory behavior and performance implications
- recognize tradeoffs between convenience and control
- understand abstraction boundaries and their consequences
- connect higher-level design decisions to lower-level system behavior
- develop intuition for why some systems require different engineering
  approaches under performance or runtime constraints

This capability surfaced more clearly through the reframing of the C++ slot and
is distinct from general architectural thinking.

---

## Capability Group 9. Testing, Validation, and Uncertainty Handling

Graduates should be prepared to validate software and AI-related outputs in
contexts where uncertainty cannot always be removed in advance.

This includes the ability to:

- test software behavior systematically
- validate AI-assisted or AI-generated outputs against requirements and
  evidence
- recognize when certainty is not yet justified
- design fallback paths, review loops, and bounded failure handling
- communicate limitations and uncertainty honestly
- avoid treating plausible output as automatically correct output

Students need stronger validation habits, not weaker ones.

---

## Capability Group 10. Collaborative Delivery and CI/CD Workflow

Graduates should understand how modern software moves through team environments
rather than treating coding as an isolated activity.

This includes the ability to:

- use version control in a disciplined way
- work with branches, pull requests, and review processes
- understand collaborative workflow and issue coordination
- recognize the role of automation and CI/CD in delivery quality
- participate in team-based delivery with accountability
- use AI assistance inside governed team workflow rather than outside it

This capability surfaced strongly through bridge replacement planning and is one
of the clearest employability gains available.

---

## Capability Group 11. Human Governance and Professional Judgment

Graduates should understand that responsibility for quality, fit, and
acceptance remains human, even when AI participates in the work.

This includes the ability to:

- maintain accountability for decisions and delivered work
- decide when to accept, revise, reject, or escalate AI-supported output
- recognize bias, overreach, and false confidence in generated material
- preserve ethical, legal, and professional boundaries
- understand that AI can expand capability without removing responsibility

This helps prevent professional judgment from collapsing into passive tool
consumption.

---

## Capability Group 12. Applied Integration and Demonstrated Capability

Graduates should be able to integrate multiple competencies into a bounded,
defensible, and demonstrable applied result.

This includes the ability to:

- combine software foundations, AI-assisted workflow, and architectural
  reasoning in one coherent artifact or system slice
- justify key design choices
- demonstrate what was built and why
- show how testing, validation, and governance were handled
- communicate the relationship between technical decisions and practical
  outcomes

This capability gives the program a stronger ending than simple exposure alone.

---

## Capability Group 13. Adaptability and Continuous Learning

Graduates should leave with the ability to keep learning in a rapidly changing
technical environment.

This includes the ability to:

- acquire new tools and concepts without losing grounding
- ask useful technical questions
- compare alternatives and learn enough to make informed choices
- update approaches when evidence or conditions change
- move between conventional, transitional, and more AI-intensive environments

The goal is not only current readiness, but durable adaptability.

---

## Cross-Cutting Program Principle

The graduate should not emerge as:

- only a conventional developer with minimal AI familiarity
- only a tool user with weak software foundations
- only a partial AI enthusiast with unclear system understanding

Instead, the graduate should emerge as a beginning software professional who
can think clearly, work responsibly, justify decisions, and contribute across a
mixed development landscape shaped by both conventional and AI-mediated
practice.

---

## What Changed from v1

Relative to the earlier capability model, this revision makes several changes
more explicit.

### Newly strengthened or newly explicit areas

- governed AI-role selection and justification
- modern data modeling across multiple paradigms
- systems-performance and abstraction awareness
- collaborative delivery and CI/CD workflow
- applied integration as a distinct culminating capability

### Areas retained but sharpened

- AI-assisted practice
- AI-injected application design
- AI-embedded systems awareness
- architectural and systems thinking
- human governance and professional judgment

---

## Working Capability Summary

An AAISE-aligned graduate capability model now appears to require strength
across at least six interacting dimensions:

- durable software foundations
- governed AI-assisted practice
- AI-injected and AI-embedded system understanding
- modern data and architectural reasoning
- professional workflow and delivery capability
- applied integration with judgment and justification

This is broader than a narrow AI-tool model and more practical than a purely
theoretical AI curriculum.

## Next Questions

- Which capabilities belong mainly to the bridge, and which should be deepened

- Which current or proposed courses are the strongest carriers for each
  capability group?
