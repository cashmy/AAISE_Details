# Semester By Semester Bridge Design v1

## Purpose

This document provides a first-pass semester-by-semester design reading for the
AI-injected bridge version of the Southwest Tech IT Software Developer program.

It is not a final course schedule.

Its purpose is to show how the bridge may progress developmentally across the
four semesters while preserving continuity with the current program structure.

---

## Overall Bridge Arc

The bridge appears strongest when it follows a developmental progression rather
than introducing AI as scattered topic insertion.

A useful overall sequence is:

1. foundations and bounded AI-assisted habits
2. data, systems, and technical depth
3. AI-injected architecture and deployment
4. delivery, integration, and applied demonstration

This creates a clearer learning arc than treating all AI-related material as a
late specialization.

---

## Semester 1: Foundations and Controlled AI Entry

### Design Role

Semester 1 should establish foundational software habits while also reshaping
the student's understanding of what modern software work now includes.

It should not become AI-heavy in a way that destabilizes core learning.

Instead, it should introduce AI carefully, visibly, and under control.

### Likely Course Roles

- `10-152-117` Python Programming
  `-> Foundations of Programming for AI-Augmented Engineers`
- `10-152-118` HTML, CSS & JavaScript
  `-> Web Foundations for AI-Augmented Engineers`
- `10-152-119` Introduction to Algorithms
  `-> Algorithmic Thinking for AI-Augmented Engineers`

### Main Outcomes

- programming fundamentals
- web fundamentals
- logic and algorithmic thinking
- early AI-assisted workflow habits
- bounded AI role awareness
- early data/API/architecture preview
- initial student understanding of Workforce Models

### Bridge Character

This semester should still feel grounded and accessible.

Its role is not to create advanced AI practitioners.

Its role is to start students correctly.

---

## Semester 2: Data, Stack Depth, and Modern Development Reasoning

### Design Role

Semester 2 should deepen technical capability while making the bridge's modern
direction more unmistakable.

This is likely the strongest hinge semester between legacy-software identity and
bridge-level AAISE alignment.

### Likely Course Roles

- `10-152-120` SQL Programming
  `-> keep practical SQL foundations in the bridge sequence`
- `10-152-121` Advanced Python Programming
  `-> notebooks, libraries, ML workflow, Django exposure`
- `10-152-122` C# Programming
  `-> keep and reframe with ASP.NET exposure folded in`
- replacement or redesign of `10-152-123 SQL Programming Advanced`
  `-> likely Modern Data Modeling for AI-Enabled Systems`
  `-> bridge order may place this after SQL, even though future AAISE design may place modeling before SQL`

### Main Outcomes

- stronger software fluency
- modern data-model understanding
- relational and non-relational reasoning
- Python-based technical depth
- exposure to ML-oriented tools and workflow
- continued AI-assisted development normalization
- WM1 employability preserved through C#/.NET

### Bridge Character

This semester should make clear that the bridge is not merely a renamed version
of the old program.

At the same time, it should still preserve strong immediate workforce value.

---

## Semester 3: AI-Injected Architecture and Applied System Context

### Design Role

Semester 3 should be where the bridge becomes structurally recognizable as
AI-injected rather than simply AI-aware.

This is the best place for stronger architectural movement.

### Likely Course Roles

- `10-152-124` Introduction to Docker and Containers
- `10-152-126` Cloud for Developers
- `10-152-127` AI-Driven Systems Analysis
  `-> full RBA application`
- `10-152-128` C++ Programming
  `-> keep and radically reframe around memory, performance, abstraction boundaries, and systems-level reasoning`
- review of `10-152-132 Mobile Development`
  `-> possibly Flutter/Dart direction if retained later`

### Main Outcomes

- deployment and packaging literacy
- cloud context for AI-enabled systems
- stronger systems framing
- RBA-based architectural reasoning
- memory and performance awareness
- abstraction-boundary reasoning
- clearer movement into WM3 and WM4

### Bridge Character

This semester should mark the student's transition from learning tools and
techniques toward designing coherent systems that can responsibly include AI.

---

## Semester 4: Delivery, Integration, and Demonstrated Capability

### Design Role

Semester 4 should function as the program's professional synthesis layer.

The bridge should end not in vague exposure, but in a more intentional
demonstration of capability.

### Likely Course Roles

- `10-152-129` Agile Practices
  `-> expanded to include GitHub, review, and CI/CD workflow`
- replacement of `10-152-130 Software Career Experience`
  `-> likely Applied AI Integration Studio or similar`
- `10-152-131` Machine Learning and AI
  `-> keep and reframe with PyTorch/TensorFlow exposure`
- removal or replacement of `10-152-133 Enterprise Data Systems & API Architecture`
  `-> likely not retained in current form`

### Main Outcomes

- team and delivery discipline
- collaborative development workflow
- pull request and CI/CD literacy
- applied AI-system integration
- model-tool exposure with practical framing
- demonstrated end-of-program capability

### Bridge Character

This semester should feel like a professional proving ground rather than a
catch-all collection of leftover advanced topics.

---

## Bridge Identity by Semester

### Semester 1

`I can code, think, and begin using AI under control.`

### Semester 2

`I understand data, tools, and modern development pathways more deeply.`

### Semester 3

`I can reason about AI as part of architecture, deployment, and system design.`

### Semester 4

`I can deliver, integrate, justify, and demonstrate applied capability.`

---

## Working Semester Summary

The semester-by-semester bridge now appears to have a coherent shape:

- Semester 1 builds controlled entry
- Semester 2 builds technical and data depth
- Semester 3 builds AI-injected system design
- Semester 4 builds professional delivery and demonstration

This is stronger than a curriculum in which AI appears only late or only in a
single specialized course cluster.

It also preserves a clean relationship to the future AAISE successor program by
allowing the bridge to become more intentional without pretending it is already
the final AI-native form.
