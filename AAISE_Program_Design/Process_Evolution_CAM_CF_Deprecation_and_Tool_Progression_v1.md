# CAM/CF Deprecation Decision

## Original Purpose

**CAM (Course Architecture)** and **CF (Competency Framework)** artifacts were created in early course development stages to:
- Provide pedagogical framework structure
- Enable design iteration space
- Establish teaching doctrine and approach
- Create initial competency mapping

## Reality Contact Evidence

Through actual practice across the first three courses (117, 118, 119), it was observed that:
- CAM and CF artifacts were never examined or referenced once WIDS competencies were crafted and approved
- The combination of WIDS competencies + high-level course plan + reading selections provided complete framework
- Additional artifacts created cognitive load without providing operational value
- Early-stage scaffolding served its purpose but was not needed for ongoing work

## Deprecation Decision

**CAM and CF are now deprecated for AAISE curriculum development.**

**Canonical Framework Going Forward:**
1. **WIDS Course Competencies** - System-required, Bloom's taxonomy-aligned competencies with learning objectives
2. **High-Level Course Plan** - Weekly structure, topics, lab directions, operational context
3. **Reading Selections** - Textbook alignment and curated content mapping
4. **MRS (Master Rubric System)** - Assessment framework aligned to WIDS competencies

## Rationale

This deprecation:
- Reduces cognitive load and artifact maintenance
- Aligns with lean governance principles
- Based on evidence from actual practice across multiple courses
- Maintains effectiveness while eliminating redundancy
- Preserves system requirements (WIDS) while removing intermediate scaffolding

# AI Tool Progression in Curriculum Development

## Tool Evolution History

### Phase 1: GPT-5+ Models
- Used for initial course development and design iteration
- Provided broad capability for content generation and framework development
- Limitations in specialized curriculum context and workflow integration

### Phase 2: GitHub Copilot Desktop Application
- Integrated development environment assistance
- Optional tool for code-specific tasks
- Limited to code completion and suggestion rather than comprehensive curriculum development

### Phase 3: Devin (Current)
- **Primary Development Tool:** Devin CLI agent system
- **Underlying LLM:** SWE-1.6 Slow model
- **Capabilities:**
  - Comprehensive curriculum development framework
  - File system operations and codebase exploration
  - Multi-step task planning and execution
  - Document creation and editing
  - Reality Contact analysis and Sky-Bounce processes
  - RBA/DAG ontology integration
  - Template/proof-of-concept development

## Devin Integration for AAISE Development

### Current Session Context
- **Template/Proof-of-Concept:** Course 123 (Modern Data Modeling for Systems)
- **Concurrent Development:** Course 120 (Database Query and Design) 
- **Process Focus:** Establishing repeatable patterns for spring semester courses

### Key Capabilities Utilized
- Codebase exploration and analysis
- Multi-document reading and synthesis
- Artifact creation with specific formatting requirements
- Reality Contact analysis and decision support
- DAG-informed workflow optimization
- RBA ontology integration without explicit terminology

### Tool Selection Rationale
Devin was selected because it provides:
- Command-line agent capabilities for file operations
- Structured workflow management
- Ability to handle complex, multi-step curriculum development tasks
- Integration with existing project structure
- Support for iterative refinement based on Reality Contact

# Process Implications

## Simplified Development Workflow

**Previous Workflow:**
1. CAM (Course Architecture)
2. CF (Competency Framework) 
3. WIDS Course Competencies
4. High-Level Course Plan
5. Reading Selections
6. MRS Development

**Current Workflow:**
1. WIDS Course Competencies
2. High-Level Course Plan
3. Reading Selections
4. MRS Development

## Benefits of Evolution

- **Reduced Artifact Overhead:** Eliminated 2 intermediate artifacts
- **Maintained Effectiveness:** Core framework preserved through remaining artifacts
- **Improved Tool Integration:** Devin provides comprehensive support for streamlined workflow
- **Evidence-Based Governance:** Decisions based on actual practice rather than theoretical frameworks
- **Faster Iteration:** Fewer steps between concept and implementation
