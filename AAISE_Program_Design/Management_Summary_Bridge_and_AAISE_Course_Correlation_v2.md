# Management Summary - Bridge and AAISE Course Correlation v2

## Purpose

This artifact provides a concise management-level summary of:

* the current bridge-program direction
* semester-by-semester goals
* currently identified bridge-level course changes
* proposed AAISE-correlated course naming

It is intended as a practical refactoring of the earlier condensed bridge matrix into a more directly discussion-ready summary.

This is not a final approved catalog.

It is a working management artifact.

---

## Framing Notes

### 1. Current Program / Bridge Context

The bridge must continue to operate inside the current approved numbering and governance structure:

* `10-152-nnn`

This means some courses may be:

* renamed directionally in internal planning
* reframed in content and competencies
* or changed only partially at the bridge level

### 2. Future AAISE Context

The future AAISE program is expected to use:

* `10-156-nnn`

This gives more latitude for cleaner AI-era course naming and broader course framing.

### 3. Naming Principle

Proposed AAISE names should be:

* clear
* modern
* generic enough to survive technology adaptation
* not over-locked to one stack or one product where avoidable

This directly supports the AI Program Velocity problem by reducing the need for resubmission whenever a stack changes.

## Locked / Gross Bridge Changes at This Stage

The major currently identified bridge changes are:

* replace `10-152-123 SQL Programming Advanced` with **Modern Data Modeling for AI-Enabled Systems**
* rename `10-152-128 C++ Programming` to **C++ Systems Performance and AI Runtime Foundations** at the bridge level
* drop `10-152-125 ASP.NET Programming` as a standalone course and merge its core exposure into C#
* rename `10-152-122 C# Programming` in the bridge to **C# & ASP.NET Programming**
* use `10-152-127 AI-Driven Systems Analysis` as the strongest current bridge location for RBA injection
* retain `10-152-130 Software Career Experience` nomenclature in the bridge, but redesign its concept toward the **Applied Software Integration Studio** model for the future AAISE structure

## Naming Notes

### Bridge-Level Naming

At the bridge level, some names may remain more technology-specific because:

* the courses still live inside the current approved structure
* the bridge must preserve legibility against the existing program
* some changes can be made directionally before full catalog redesign

### AAISE-Level Naming

At the AAISE level, naming should become:

* more concept-driven
* less stack-locked
* more durable across likely technology shifts

This is why Semester 1 naming is currently the strongest model:

* it preserves the instructional identity
* while avoiding unnecessary lock-in to one toolset

That same principle should guide later AAISE course names wherever possible.
