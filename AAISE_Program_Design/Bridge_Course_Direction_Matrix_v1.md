# Bridge Course Direction Matrix v1

## Purpose

This document provides a first-pass directional matrix for the AI-injected
bridge version of the current Southwest Tech IT Software Developer program.

It is not a final curriculum map.

Its purpose is to identify, course by course, which `10-152` and closely
related software slots should likely be:

- retained
- reframed
- expanded
- reduced
- replaced
- or treated as likely divergence points between the bridge and future AAISE
  successor program

---

## How to Read This Matrix

This matrix is directional rather than final.

It reflects the current state of the design conversation, including:

- existing bridge implementation patterns already visible in course redesign
- current governance constraints
- the four Workforce Models
- the distinction between bridge logic and successor-program logic

The point is not to force premature certainty.

The point is to create enough structure that later redesign decisions can be
made more coherently.

## Emerging Pattern by Semester

### Semester 1

Semester 1 appears best suited for:

- foundational skill preservation
- alternate-title reframing
- early workforce-model exposure
- bounded AI-assisted practice
- early data/API/architecture preview

This semester should likely remain highly stable structurally while becoming
more intentional conceptually.

### Semester 2

Semester 2 appears best suited for:

- deeper technical fluency
- stronger AI-assisted workflow normalization
- data modeling and data-system reasoning
- stack and integration decisions that begin to shape later divergence

This semester may become the most important bridge-to-successor hinge point.

### Semester 3

Semester 3 appears best suited for:

- stronger AI-injected design logic
- cloud and container deployment context
- systems analysis
- first larger divergence decisions from legacy structure

This is one of the best semesters for more aggressive bridge moves.

### Semester 4

Semester 4 appears best suited for:

- team and delivery workflow
- CI/CD and governed development practice
- applied integration experience
- enterprise/data/API integration
- bounded advanced AI exposure where appropriate

This is also a likely major divergence zone between bridge and successor forms.

## Working Interpretation

The bridge version does not appear to require wholesale destruction of the
current `10-152` structure.

Instead, the current picture suggests a more selective pattern:

- keep and reframe the strongest carriers
- modernize the data and workflow spine
- review stack-breadth courses for strategic fit
- use later semesters for stronger AI-injected integration
- reserve the most AI-native structural departures for the successor program

This is consistent with the bridge's role as a transition architecture rather
than a disguised full replacement.
