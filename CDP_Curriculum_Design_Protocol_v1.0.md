# 📘 Curriculum Design Protocol (CDP) — v1.0
### *Sequential Architecture for AI-Augmented Course Design*

---

## 🔹 Overview

The Curriculum Design Protocol (CDP) defines a repeatable process for rapidly designing high-quality, AI-augmented courses that remain institutionally compliant while preserving modern instructional intent.

This protocol enables movement from:

> Idea → Structured Course → Deployable Curriculum

Each step includes:
- Purpose
- Core Actions
- Artifacts

---

# 🔻 Phase 1 — Context & Constraint Ingestion

## Step 1 — Constraint Definition
**Purpose:** Anchor design in reality before creativity begins.

**Core Actions:**
- Identify course title, catalog description
- Define credit hours and schedule
- Identify prerequisites
- Capture institutional requirements (e.g., WIDS)

**Artifacts:**
- Constraint Sheet (CS-01)

---

## Step 2 — Learner Baseline Modeling
**Purpose:** Define the true starting point of students.

**Core Actions:**
- Assess technical ability
- Evaluate cognitive maturity
- Identify exposure to AI/tools

**Artifacts:**
- Learner Profile (LP-01)

---

## Step 3 — Outcome Identity Framing
**Purpose:** Define what the student becomes.

**Core Actions:**
- Complete: “After this course, the student is able to…”
- Define capability, behavior, mindset

**Artifacts:**
- Outcome Identity Statement (OIS-01)

---

# 🔻 Phase 2 — Structural Encoding

## Step 4 — Competency Encoding (WIDS Layer)
**Purpose:** Translate intent into institutional structure.

**Core Actions:**
- Define 5–7 competencies
- Add assessment strategies
- Define criteria (observable behaviors)
- Add learning objectives

**Artifacts:**
- Competency Framework (CF-01)

---

## Step 5 — Teaching Doctrine Definition
**Purpose:** Define how learning occurs.

**Core Actions:**
- Establish AI usage model
- Define thinking vs implementation balance
- Set instructional philosophy

**Artifacts:**
- Teaching Doctrine (TD-01)

---

# 🔻 Phase 3 — Course Architecture

## Step 6 — Temporal Architecture Design
**Purpose:** Map learning progression over time.

**Core Actions:**
- Define phases
- Build weekly structure
- Establish instructional rhythm

**Artifacts:**
- Course Architecture Map (CAM-01)

---

## Step 7 — Content Curation
**Purpose:** Select essential material (depth over breadth).

**Core Actions:**
- Identify key concepts
- Select algorithms/topics
- Remove non-essential content

**Artifacts:**
- Content Selection Matrix (CSM-01)

---

# 🔻 Phase 4 — Behavioral System Design (Labs)

## Step 8 — Lab Framework Definition
**Purpose:** Create repeatable lab structure.

**Core Actions:**
- Define standard lab phases:
  - Problem framing
  - Manual solution
  - AI-assisted solution
  - Evaluation
  - Adaptation

**Artifacts:**
- Lab Template (LT-01)

---

## Step 9 — Weekly Lab Design
**Purpose:** Apply lab framework to progression.

**Core Actions:**
- Define weekly problems
- Increase complexity
- Progress AI involvement

**Artifacts:**
- Lab Series (LS-01)

---

# 🔻 Phase 5 — Evaluation System

## Step 10 — Rubric Construction
**Purpose:** Ensure consistent grading.

**Core Actions:**
- Define categories:
  - Problem framing
  - Manual implementation
  - AI usage
  - Evaluation
  - Adaptation

**Artifacts:**
- Grading Rubric (GR-01)

---

## Step 11 — Assessment Strategy Alignment
**Purpose:** Align evaluation with competencies.

**Core Actions:**
- Map competencies to labs and rubric
- Define quiz strategy

**Artifacts:**
- Assessment Mapping Matrix (AMM-01)

---

# 🔻 Phase 6 — Instructional Support System

## Step 12 — AI Interaction Protocol
**Purpose:** Guide effective AI usage.

**Core Actions:**
- Define prompt templates
- Establish usage rules
- Define progression model

**Artifacts:**
- AI Usage Guide (AIUG-01)

---

## Step 13 — Instructor Observation Guide
**Purpose:** Support real-time instruction.

**Core Actions:**
- Identify failure patterns
- Define intervention strategies
- Establish coaching questions

**Artifacts:**
- Instructor Playbook (IP-01)

---

# 🔻 Phase 7 — Translation & Deployment

## Step 14 — Institutional Translation
**Purpose:** Prepare for submission.

**Core Actions:**
- Format WIDS documentation
- Generate syllabus

**Artifacts:**
- WIDS Submission Package (WSP-01)
- Course Syllabus (SYL-01)

---

## Step 15 — Program Alignment Pass
**Purpose:** Ensure curriculum coherence.

**Core Actions:**
- Align with prior courses
- Align with future courses
- Ensure program identity consistency

**Artifacts:**
- Program Alignment Map (PAM-01)

---

# 🔹 Full Pipeline (Condensed)

1. Constraints
2. Learner Model
3. Outcome Identity
4. Competencies
5. Teaching Doctrine
6. Course Architecture
7. Content Selection
8. Lab Framework
9. Weekly Labs
10. Rubric
11. Assessment Mapping
12. AI Protocol
13. Instructor Guide
14. Institutional Translation
15. Program Alignment

---

# 🔹 Key Principles

- Alignment before execution
- Behavior is designed, not assumed
- AI is integrated, not appended
- Institutional compliance without conceptual compromise
