# MASTER RUBRIC SYSTEM (MRS-AL) - Algorithmic Problem Solving

---

# PART 1 - STRUCTURE

Each assignment uses a consistent rubric structure, but not every assignment
must emphasize every category equally.

The goal is to support fast, repeatable grading while aligning assessment to the
actual arc of `10-152-119 Introduction to Algorithms`.

This course evaluates algorithmic judgment: how students define problems, choose
structures, implement and test solutions, compare performance, use evidence, and
explain tradeoffs. AI use is assessed when it is part of the assignment, but AI
does not replace the central course target of reasoning about algorithms.

---

## Performance Scale

| Score | Level |
| ----- | ----- |
| 4 | **Exceeds** |
| 3 | **Meets** |
| 2 | **Developing** |
| 1 | **Needs Improvement** |

# PART 2 - TECHNICAL COMPETENCIES

Technical competencies are course-specific and aligned to problem analysis, data
structures, implementation, testing, performance reasoning, visual/tangible
evidence, AI/data bridge concepts, and responsible AI-assisted tool use.

To keep grading manageable, this system uses **6 technical categories** rather
than creating a separate category for every algorithm or textbook chapter.

---

## T1. Problem Framing and Algorithmic Analysis

**Evidence:** problem statement, inputs, outputs, constraints, assumptions, edge
cases, pseudocode, diagrams, traces

| Level | Description |
| ----- | ----------- |
| **4 - Exceeds** | Clearly defines the problem, constraints, assumptions, and edge cases; represents the solution approach with precise logic before implementation |
| **3 - Meets** | Defines the problem and intended approach with minor gaps that do not prevent meaningful implementation |
| **2 - Developing** | Provides partial framing, but important inputs, constraints, assumptions, or edge cases are missing or unclear |
| **1 - Needs Improvement** | Begins coding or using tools without a clear problem definition or algorithmic approach |

---

## T2. Data Structures and Representation

**Evidence:** lists, dictionaries, sets, stacks, queues, trees, graphs,
adjacency lists, matrices/tables, representation choices

| Level | Description |
| ----- | ----------- |
| **4 - Exceeds** | Selects and uses data structures purposefully; clearly explains how representation affects clarity, access, traversal, lookup, or performance |
| **3 - Meets** | Uses appropriate data structures for the task with minor inefficiencies or explanation gaps |
| **2 - Developing** | Uses some structures correctly, but representation choices are fragile, inefficient, or weakly justified |
| **1 - Needs Improvement** | Uses inappropriate or unclear structures that prevent the algorithm from working or being explained |

---

## T3. Algorithm Implementation and Testing

**Evidence:** Python implementation, pseudocode-to-code translation, search,
sort, recursion/iteration, graph traversal, normal tests, edge tests, expected
outcomes

| Level | Description |
| ----- | ----------- |
| **4 - Exceeds** | Implements the algorithm accurately and readably; tests normal and edge cases; can explain why the results support correctness |
| **3 - Meets** | Implements the required algorithm with minor issues; uses reasonable tests to check expected behavior |
| **2 - Developing** | Implementation is partially correct but has logic gaps, limited tests, or unclear connection to the intended algorithm |
| **1 - Needs Improvement** | Implementation is missing, nonfunctional, or not meaningfully connected to the algorithmic task |

---

## T4. Correctness, Efficiency, and Tradeoff Evaluation

**Evidence:** correctness checks, Big-O vocabulary, timing data, comparison of
solutions, simplicity vs performance, readability, maintainability, assumptions

| Level | Description |
| ----- | ----------- |
| **4 - Exceeds** | Evaluates correctness and efficiency with clear evidence; compares tradeoffs among approaches using appropriate vocabulary and reasoning |
| **3 - Meets** | Provides a reasonable correctness and efficiency comparison with minor gaps in evidence or explanation |
| **2 - Developing** | Makes limited or mostly unsupported claims about correctness, performance, or tradeoffs |
| **1 - Needs Improvement** | Does not meaningfully evaluate whether the solution works, scales, or fits the problem |

---

## T5. Observable Algorithm Behavior and Communication Evidence

**Evidence:** traces, timing tables, charts, grid simulations, graph diagrams,
traversal orders, search/sort steps, similarity matrices, clustering plots,
ranking tables

| Level | Description |
| ----- | ----------- |
| **4 - Exceeds** | Uses clear visual or tangible evidence to make algorithm behavior observable and connects that evidence to the explanation |
| **3 - Meets** | Provides appropriate evidence that supports the main explanation with minor clarity gaps |
| **2 - Developing** | Provides limited evidence, or evidence is present but weakly connected to the algorithmic claim |
| **1 - Needs Improvement** | Provides little or no evidence beyond claiming that the code runs |

---

## T6. AI/Data Foundations and Responsible Tool Use

**Evidence:** similarity, clustering, recommendation, hashing, representation,
AI-assisted explanation, AI-injected code help, validation of generated output,
limitations, bias, assumptions, disclosure

| Level | Description |
| ----- | ----------- |
| **4 - Exceeds** | Connects algorithmic ideas to AI/data contexts accurately; uses AI or other tools transparently, validates output, identifies assumptions, and explains human decisions |
| **3 - Meets** | Recognizes relevant AI/data connections and uses AI-assisted tools appropriately when allowed, with basic validation and explanation |
| **2 - Developing** | Shows partial understanding of AI/data connections or uses tools with limited validation, unclear attribution, or weak explanation |
| **1 - Needs Improvement** | Relies on AI/tool output without understanding, validation, or explanation; cannot identify assumptions or limitations |

# PART 3 - CORE ABILITIES

Core abilities are behavioral and professional competencies that can be observed
across assignments, labs, discussions, and presentations.

These categories remain consistent across the bridge courses, but the evidence
language below is specific to Algorithmic Problem Solving.

---

## C1. Solve Problems

**Evidence:** decomposition, troubleshooting, strategy selection, persistence,
debugging, recovery from incorrect assumptions

| Level | Description |
| ----- | ----------- |
| **4 - Exceeds** | Consistently analyzes problems, tests assumptions, recovers from errors, and selects effective strategies independently or with well-targeted support |
| **3 - Meets** | Resolves most problems with reasonable effort and limited guidance |
| **2 - Developing** | Attempts problem solving but needs frequent support to identify issues or choose next steps |
| **1 - Needs Improvement** | Struggles to identify, analyze, or recover from algorithmic problems |

---

## C2. Communicate Clearly

**Evidence:** algorithm explanation, tradeoff explanation, pseudocode, diagrams,
evidence discussion, AI/tool-use justification, presentation

| Level | Description |
| ----- | ----------- |
| **4 - Exceeds** | Clearly explains algorithmic choices, evidence, tradeoffs, assumptions, and limitations to technical or non-technical audiences |
| **3 - Meets** | Communicates the main solution and reasoning adequately with minor gaps |
| **2 - Developing** | Explanation is incomplete, vague, or difficult to connect to the submitted work |
| **1 - Needs Improvement** | Cannot clearly explain the algorithm, evidence, or decision-making process |

---

## C3. Work Productively

**Evidence:** lab focus, task completion, organized files/submissions, use of
time, meeting checkpoints

| Level | Description |
| ----- | ----------- |
| **4 - Exceeds** | Uses time effectively, stays organized, completes tasks reliably, and makes strong progress during lab work |
| **3 - Meets** | Generally productive with minor lapses in focus, organization, or completion |
| **2 - Developing** | Productivity is inconsistent or requires frequent redirection |
| **1 - Needs Improvement** | Frequently off-task, incomplete, or unable to make meaningful progress |

---

## C4. Value Learning

**Evidence:** textbook/reference use, feedback application, revision, curiosity,
responsible AI/tool use, willingness to compare approaches

| Level | Description |
| ----- | ----------- |
| **4 - Exceeds** | Actively uses resources, applies feedback, asks useful questions, revises work, and deepens understanding through comparison |
| **3 - Meets** | Uses resources and feedback appropriately with some guidance |
| **2 - Developing** | Uses resources inconsistently or applies feedback only partially |
| **1 - Needs Improvement** | Does not meaningfully engage with learning resources, feedback, revision, or comparison |

---

## C5. Work Cooperatively

**Evidence:** peer explanation, partner testing, code/logic walkthroughs,
respectful critique, shared problem solving

| Level | Description |
| ----- | ----------- |
| **4 - Exceeds** | Actively contributes, supports peers, gives useful feedback, shares responsibility, and collaborates respectfully |
| **3 - Meets** | Participates appropriately with minor imbalance or limited initiative |
| **2 - Developing** | Collaboration is inconsistent, passive, or requires support |
| **1 - Needs Improvement** | Does not effectively collaborate or interferes with productive group work |

---

## C6. Act Professionally

**Evidence:** preparedness, respectful conduct, academic integrity, tool-use
transparency, presentation quality, readiness for lab and discussion

| Level | Description |
| ----- | ----------- |
| **4 - Exceeds** | Consistently prepared, respectful, engaged, accountable, and transparent about work process and tool use |
| **3 - Meets** | Generally professional with minor issues |
| **2 - Developing** | Professionalism, preparation, accountability, or engagement is inconsistent |
| **1 - Needs Improvement** | Behavior, preparation, integrity, or engagement does not meet course expectations |

# PART 4 - SCORING MODEL

---

## Schoology-Friendly Model

- Each category uses the same **0-4** scale.
- Rubric rows can be reused across assignments.
- Assignment emphasis can be adjusted by selecting the most relevant rows or
  weighting selected rows more heavily.

---

## Total Categories

- 6 Technical Competencies
- 6 Core Abilities

If every category is used on an assignment:

**48 points total = 12 categories x 4 points**

However, most assignments should not need every row.

For grading efficiency, use the Assignment Mapping Matrix to select or emphasize
the most relevant categories.

---

## Recommended Practical Use

For smaller assignments:

- use 3-5 rubric rows
- emphasize the technical skill being practiced
- include 1-2 core ability rows when observable

For larger assignments and final applied work:

- use more rubric rows
- include correctness, efficiency, evidence, and communication
- include AI/tool-use accountability when AI is allowed or required

# PART 6 - IMPLEMENTATION NOTES

---

## In Schoology

Each row can become one rubric criterion.

Recommended workflow:

1. Create the full master rubric once.
2. Duplicate or select relevant rows per assignment.
3. Use the AMM to decide which rows should be emphasized.
4. Keep the 0-4 scale consistent.

---

## Instructor Workflow

1. Identify the assignment's primary and secondary rubric rows from the AMM.
2. Score the technical evidence first.
3. Score core abilities only where observable.
4. Add comments only when they clarify revision, misunderstanding, evidence, or
   exceptional performance.

---

## Evaluation Frequency

Light scoring can occur weekly, but stronger evaluation should occur at natural
checkpoints:

- Week 2: problem framing, correctness, and Big-O growth intuition
- Week 4: data structures, search/sort behavior, and assumptions
- Week 6: strategy comparison, graphs, and observable behavior
- Week 8: synthesis demo/practice, final Applied Solution Set, and final
  Personalized Explanation Defense

---

## AI Involvement Scoring Notes

Use the course AI progression consistently:

```text
Manual First -> AI-Assisted -> AI-Injected -> AI-Integrated
```

- Manual First is expected before AI-supported critique or implementation.
- AI-Assisted use includes explanation, vocabulary, research, comparison, and
  critique.
- AI-Injected use includes AI coding help and requires student testing,
  justification, and explanation.
- AI-Integrated use is optional or preview-level in this course and should only
  be assessed when the final task is explicitly structured for it.

Do not penalize students for not using AI unless an assignment specifically
requires it. Do assess whether AI use, when present, is transparent, validated,
and explainable.

---

# FINAL SYSTEM STATEMENT

This rubric system keeps grading consistent while allowing assignments to
emphasize different parts of the course arc.

Students are assessed not only on whether a solution runs, but also on whether
they can define the problem, choose useful structures, test correctness, compare
efficiency, provide evidence, use AI-assisted tools responsibly, and explain
algorithmic tradeoffs clearly.
