# MVP DEVELOPMENT PROGRESSION - INSTRUCTIONAL ARTIFACT

**Reusable lecture reference**

---

# Purpose

This artifact captures a simple development progression that can be reused in
lecture slides, demos, and assignment discussion across multiple courses.

The progression connects introductory programming work to quality Agile/MVP
practice.

---

# Core Idea

Do not begin by trying to make the solution impressive.

Begin by making the smallest useful version work, then improve it in disciplined
steps.

---

# The Progression

## 1. Make It Correct

First, prove the core behavior works.

The solution should solve the assigned problem for normal cases and expected
inputs.

Guiding question:

```text
Does the solution produce the right result for the right reason?
```

---

## 2. Make It Observable

Next, make the behavior visible.

Use tests, output tables, traces, timing results, diagrams, or other evidence
that lets someone inspect what happened.

Guiding question:

```text
Can someone see what the solution did?
```

---

## 3. Make It Explainable

Then explain the reasoning.

Document assumptions, constraints, edge cases, tradeoffs, limitations, and any
AI assistance used.

Guiding question:

```text
Can someone understand why this approach makes sense?
```

---

## 4. Make It Usable Or Readable

After the core behavior and evidence are sound, improve readability and user
experience.

This may include clearer output, better formatting, colorized console output,
labels, cleaner prompts, or improved organization.

Guiding question:

```text
Does the presentation help someone interpret the result?
```

---

## 5. Refine Without Changing The Target

Finally, improve the solution without losing the original goal.

Enhancements should clarify or strengthen the work. They should not distract
from correctness, evidence, or explanation.

Guiding question:

```text
Did the refinement improve the solution without changing what it was supposed
to prove?
```

---

# Slide-Friendly Summary

```text
Correct -> Observable -> Explainable -> Usable -> Refined
```

Or:

```text
Make it work.
Make it visible.
Make it understandable.
Make it easier to read or use.
Improve it without changing the target.
```

---

# Instructional Framing

This progression helps students understand that better software is not merely
prettier software.

Better software is progressively clarified:

1. behavior
2. evidence
3. reasoning
4. presentation
5. refinement

Visual polish, such as colorized console output, belongs after the required
logic and evidence are working. Presentation should serve meaning.

---

# Agile / MVP Connection

This mirrors quality Agile and MVP practice.

The goal is not to build everything at once.

The goal is to deliver a small working slice, inspect it, explain it, and then
improve it intentionally.

---

# Example Use In Class

An instructor may show a plain successful solution first, then show a refined
version with clearer console output.

The teaching point is that refinement should clarify the evidence. It should
not replace correctness, testing, or explanation.
