# Purpose

This template is designed for the Algorithms course and is based on the:

- Instructional Intent Matrix
- Unit and week descriptions
- Textbook coverage and reference map
- Lab progression ladder
- Master rubric system

It is meant to keep each lecture aligned to:

- the unit and week theme
- the day's readiness target
- the lab activity the session supports
- the visible algorithm behavior students need to inspect
- the AI involvement level for the session
- the watch points that could create drift, overload, or false confidence

This template assumes live class sessions. It does not include a required
video/asynchronous lecture layer.

# 3. Review / Bridge From Prior Week (5-12 minutes)

**Goal:** reconnect students to prior work before introducing new material

For Week 1:

- mark this section as not applicable
- briefly orient students to the course structure instead

For Weeks 2-8, include:

- prior lab or activity being reviewed
- selected solution pattern or successful-version discussion
- common errors, misconceptions, or questions from the previous week
- one or two short explanation prompts students should be able to answer
- bridge statement connecting the previous week's evidence to the new material

Suggested stem:

> "Last week, you proved ______ by using ______. This week, we will use that
> same kind of evidence to reason about ______."

Guideline:

- this is a bridge, not a full reteach
- focus on the prior work needed for today's readiness target

# 7. Algorithm Visibility / Demo Plan (10-20 minutes)

**Goal:** make the algorithm's behavior concrete and inspectable

For each demo, include:

- file, artifact, or prompt name
- what the demo shows
- what students should notice
- what evidence the demo produces

Possible evidence forms:

- trace table
- timing table
- growth chart
- decision diagram
- grid or graph traversal
- sorted vs unsorted comparison
- similarity/ranking output
- assumption or edge-case checklist

Guidelines:

- keep demos small
- prefer contrast when useful
- explicitly say what the demo is proving
- separate "it ran" from "it is correct and explainable"

# 9. Common Mistakes / Watch-Fors (5-8 minutes)

**Goal:** prevent predictable frustration and false confidence

List `2-4` likely errors or misunderstandings.

For each one, include:

- what students may do
- why it happens
- how you will frame or correct it

Common Algorithms watch-fors include:

- confusing working output with correctness
- ignoring input assumptions or preconditions
- comparing timing results without controlling input size
- choosing a data structure by habit instead of access pattern
- accepting AI-generated code without tracing or explaining it
- using algorithm vocabulary without connecting it to evidence

# 10. AI Use Frame (3-6 minutes)

**Goal:** keep AI use intentional, accountable, and aligned with the course
stage

Identify the session's expected AI role:

- Manual First
- AI-Assisted
- AI-Injected
- AI-Integrated, if explicitly appropriate

Include:

- when students may use AI
- what they must do before using AI
- what they must explain, test, trace, or justify after using AI

Suggested stem:

> "AI can help with ______ after you have already ______. You are still responsible for ______."

---

# 11. Explain / Checkpoint Questions (3-8 minutes)

**Goal:** verify readiness before students leave the session

Include a small set of prompts such as:

- What problem is this algorithm solving?
- What assumptions must be true before this approach works?
- What data structure is being used, and why?
- What input causes this approach to slow down?
- What evidence shows that this result is correct?
- What tradeoff did this approach make?
- What would you need to explain if AI helped produce this code?

These should connect directly to the readiness target.

# Use Guidance

## Do

- keep the outline tightly aligned to readiness
- use demos to make algorithm behavior visible
- require evidence before explanation
- name assumptions explicitly
- preserve the session micro-arc
- keep textbook references selective and purposeful

## Do Not

- turn one lecture into a textbook dump
- introduce advanced algorithms just because they appear in the text
- treat visual output as proof by itself
- allow AI output to replace tracing, testing, or explanation
- assume students know a concept that has not been directly modeled
