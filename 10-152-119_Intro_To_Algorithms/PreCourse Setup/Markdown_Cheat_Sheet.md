# **Markdown Cheat Sheet**

---

## **Purpose**

Markdown is a simple way to format text files.

In programming courses, you may use Markdown for `README.md` files in GitHub.

GitHub automatically displays Markdown as a formatted page.

---

## **Headings**

Use `#` symbols for headings.

```markdown
# Main Heading
## Section Heading
### Smaller Heading
```

---

## **Bold And Italic**

```markdown
**bold text**
*italic text*
```

Result:

**bold text**

*italic text*

---

## **Bulleted Lists**

```markdown
- first item
- second item
- third item
```

Result:

- first item
- second item
- third item

---

## **Numbered Lists**

```markdown
1. first step
2. second step
3. third step
```

Result:

1. first step
2. second step
3. third step

---

## **Code Blocks**

Use triple backticks before and after code.

````markdown
```python
print("Hello")
```
````

Result:

```python
print("Hello")
```

---

## **Inline Code**

Use backticks for short code items inside a sentence.

```markdown
The file should be named `lab_01_solution.py`.
```

Result:

The file should be named `lab_01_solution.py`.

---

## **Tables**

Use vertical bars and dashes to create a table.

```markdown
| Test | Input | Expected | Actual | Pass? |
| --- | --- | --- | --- | --- |
| 1 |  |  |  |  |
| 2 |  |  |  |  |
```

Result:

| Test | Input | Expected | Actual | Pass? |
| --- | --- | --- | --- | --- |
| 1 |  |  |  |  |
| 2 |  |  |  |  |

---

## **Links**

```markdown
[GitHub](https://github.com)
```

Result:

[GitHub](https://github.com)

---

## **Images**

If a lab requires an image or screenshot, place the image in your lab folder and
link to it.

```markdown
![Short description](image_file_name.png)
```

Use images only when the lab or instructor asks for them.

---

## **Line Breaks**

Markdown may combine nearby lines into one paragraph.

To make separate paragraphs, leave a blank line between them.

```markdown
This is one paragraph.

This is another paragraph.
```

---

## **Good README Habits**

Use clear headings.

Keep your evidence tables readable.

Use code blocks for code or pseudocode.

Do not paste large amounts of unrelated output.

Make sure someone can understand what you did without asking you where the rest
of the submission is.
