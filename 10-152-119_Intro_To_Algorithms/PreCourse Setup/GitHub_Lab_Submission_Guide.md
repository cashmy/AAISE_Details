# **GitHub Lab Submission Guide**

---

## **Purpose**

This guide explains how to organize programming lab submissions using
GitHub.

In programming courses, your code, evidence, and explanations should usually stay
together in one place.

Unless your instructor tells you otherwise, GitHub is the main location for
your lab work. Schoology may still be used to submit a link, confirmation
message, exported PDF, or other item requested by your instructor.

---

## **Why This Matters**

Programming work is more than code.

A complete lab submission should show:

* what problem you solved
* what code you wrote
* what evidence you collected
* what assumptions you made
* what your results mean
* how AI was used, if AI was allowed and used

Keeping these items together makes your work easier to review and easier to
explain later.

---

## **Recommended Folder Pattern**

Use a separate folder for each lab.

Example:

```text
Course_Repository/
  Lab_01/
    README.md
    lab_01_solution.py
  Lab_02/
    README.md
    lab_02_solution.py
  Lab_03/
    README.md
    lab_03_solution.py
```

Your instructor may provide a different structure. If so, follow the structure
your instructor provides.

---

## **What Goes In The Code File**

Your code file should contain the code needed for the lab.

Use a clear file name such as:

```text
lab_01_solution.py
lab_02_solution.py
lab_03_project.html
lab_04_script.js
```

Your code should be readable and should match the lab requirements.

If the lab requires output, timing evidence, or test results, your code should
make that evidence easy to see or reproduce.

---

## **What Goes In The README.md File**

Your `README.md` file is the written part of the lab submission.

It should include the required evidence and explanation for the lab.

Depending on the lab, this may include:

* problem statement
* inputs and outputs
* assumptions or constraints
* pseudocode, planning notes, or technical explanation
* test table
* timing table
* comparison table
* screenshots or links, if required
* reflection or explanation
* walkthrough-use explanation, if applicable
* AI-use note, if applicable

## **Basic Submission Checklist**

Before submitting, make sure your lab folder includes:

* `README.md`
* your code solution file or files
* any required data file, if the lab uses one
* all required evidence tables
* your reflection or explanation
* your AI-use note, if applicable

Also make sure:

* your GitHub work is saved and pushed
* your repository or lab folder is accessible as required
* your Schoology submission includes the GitHub link or item requested by your
  instructor

---

## **Submitting Through Schoology**

Your instructor may ask you to submit one of the following in Schoology:

* a link to your GitHub repository
* a link to the specific lab folder or file
* a short confirmation message
* an exported or printed copy of your `README.md`
* another item specified in the assignment

GitHub should remain the main source of your code, evidence, and explanation
unless your instructor tells you otherwise.

---

## **Viewing And Exporting Markdown**

GitHub automatically displays `README.md` files as formatted pages.

If a printable or exportable copy is needed:

1. Open the `README.md` file in GitHub.
2. Use the browser print option.
3. Choose **Save as PDF** if a PDF is required.

Your instructor will tell you if this is needed.

---

## **Common Mistakes To Avoid**

Avoid these common problems:

* submitting only the Python file with no explanation
* putting the explanation only in a Schoology comment
* forgetting the evidence table
* forgetting to push the latest version to GitHub
* using a file name that is difficult to identify
* submitting AI-generated content without explaining how it was checked or
  revised

---

## **Simple Rule**

If someone opens your lab folder in GitHub, they should be able to find the
code, evidence, and explanation without hunting through separate locations.
