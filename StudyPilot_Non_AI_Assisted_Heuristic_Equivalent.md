# StudyPilot Non-AI-Assisted Heuristic Equivalent

---

## Purpose

This artifact estimates the likely effort required to produce the StudyPilot output set without AI-assisted refraction, orchestration, and iterative prompt-driven generation.

It is heuristic, not scientific.

Its purpose is to provide a realistic human-effort comparison for the same general output family.

---

## Output Scope Considered

The comparison assumes production of:

* governing document refactors
* prompt artifacts
* full console version
* full architecture-preview version
* full Django preview version
* `8` weekly milestone versions
* `1` bridge milestone version
* `9` comparison / transition artifacts
* instructor notes
* README and explanation artifacts across versions

This is not just one app.

It is a multi-version instructional software artifact system.

---

## Heuristic Time Table

| Work Area | Likely Non-AI Solo Effort |
|---|---:|
| Governing document refactors | `3-6 hrs` |

| Architecture preview version | `4-8 hrs` |
| Django preview version | `16-32 hrs` |

| 9 comparison / transition artifacts | `6-12 hrs` |
| Instructor notes, readmes, explanation docs | `4-8 hrs` |

---

## Practical Reading

A realistic solo non-AI-assisted effort for this output would likely land much closer to:

* the middle-to-upper part of the range

than the lower bound.

That suggests a more believable working estimate of:

* `80-115 hrs`

for comparable output quality, continuity, and preserved iterations.

---

## Why the Lower Bound Is Probably Too Low

The lower bound assumes unusually strong uninterrupted productivity and low revision friction.

In practice, this kind of work usually incurs heavy human cost from:

* context switching
* continuity reconstruction
* pedagogical comparison thinking
* iterative simplification across milestone versions
* write-review-rewrite loops
* UI/UX judgment and tinkering for the Django preview
* deciding what to preserve and what to intentionally omit at each stage

This means the visible code volume is misleading.

The real cost is in:

* conceptual sequencing
* structural coherence
* preserved bounded differences between versions

---

## Cognitive Load Interpretation

Without AI assistance, the largest hidden burden would likely come from:

* repeatedly re-deriving the milestone sequence
* manually creating each simplified iteration
* writing and maintaining all comparison artifacts
* preserving continuity between the three full versions
* avoiding drift between curriculum intent and software behavior

This would be especially draining because the work spans more than one domain:

* software design
* pedagogy
* documentation
* process governance

---

## Compression Estimate

If the AI-assisted run took approximately:

* `2.5 hrs`

then the rough compression ratio compared with non-AI solo effort is approximately:

* `24x-48x` against the full heuristic range

or more realistically:

* `32x-46x`

against the more believable `80-115 hr` band.

---

## Most Important Caveat

The compression did not happen because AI "wrote code fast."

It happened because AI reduced the cost of:

* version derivation
* structural re-expression
* continuity maintenance
* comparison artifact generation
* prompt operationalization

while the human preserved:

* scope
* pedagogy
* sequencing
* semantic arbitration
* version honesty

---

## Final Heuristic Conclusion

A comparable non-AI-assisted StudyPilot output would likely require:

* `80-115 hrs` in realistic solo conditions

and could plausibly exceed that if interruption, review friction, or redesign cycles increased.

The AI-assisted run therefore represents not just faster coding, but a major compression of:

* multi-version software development
* instructional alignment work
* comparison and explanation work
* continuity preservation effort

That is what makes the output level so striking.
