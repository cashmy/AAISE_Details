# Copilot App Practical Workflow Guide

**Student Guide**

## Purpose

This guide gives a beginner-safe workflow for using the GitHub Copilot app
later in the program.

The Copilot app should not be treated as a shortcut for beginner assignments.
It is more appropriate once you are ready to manage plans, branches, sessions,
reviews, and AI-generated changes responsibly.

## Before You Start

Ask:

- Is AI use allowed for this assignment?
- Is agent-style help allowed, or only explanation?
- Am I allowed to let AI edit files?
- Can I explain the existing code before changing it?
- Do I have a backup or GitHub copy?

If the answer is unclear, ask the instructor first.

## Recommended Workflow

### 1. Start With Inspection

Do not begin with:

```text
Fix this project.
```

Start with:

```text
Inspect this project.
Summarize the relevant files.
Do not edit anything yet.
```

### 2. Ask For A Plan

Before allowing edits, ask for a plan.

```text
Create a short plan for the change.
List the files you think need to change.
Do not edit yet.
Ask clarifying questions if needed.
```

### 3. Review The Plan

Check:

- does the plan match the assignment?
- is the scope too large?
- does it change files that should not change?
- does it skip required evidence?
- can you explain the plan?

If not, ask for a smaller plan.

### 4. Give Narrow Permission

If edits are allowed, give limited permission.

```text
Make only the changes in the approved plan.
Do not add new features.
Do not change unrelated files.
After editing, summarize every file changed.
```

### 5. Review The Changes

After edits, review:

- changed files
- code behavior
- comments or explanations
- deleted code
- added dependencies
- assignment requirements

Do not accept changes just because they look polished.

### 6. Test It Yourself

You still need to:

- run the project
- test the behavior
- check console or terminal output
- verify requirements
- update README/evidence if required

### 7. Explain What You Accepted

Before submitting, write or say:

- what changed
- why it changed
- how you tested it
- what AI helped with
- what you personally verified

## Good Uses Later In The Program

The Copilot app may be useful for:

- exploring a larger repository
- creating an implementation plan
- comparing possible approaches
- generating a checklist
- preparing a small refactor
- reviewing a pull request or branch
- managing separate work sessions

## Risky Uses

Be careful with prompts like:

- "Build the whole project."
- "Rewrite this for me."
- "Make it professional."
- "Fix everything."
- "Do the assignment."

These prompts are too broad and can remove student ownership.

## Safe Ending Checklist

Before you submit work influenced by the Copilot app:

- I know what files changed.
- I tested the project.
- I understand the code.
- I can explain the result.
- I followed assignment AI rules.
- I disclosed AI use if required.
- I did not submit code I cannot explain.
