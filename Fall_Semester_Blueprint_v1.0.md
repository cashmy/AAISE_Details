# 📘 AAISE Program — Semester 01 Blueprint (v1.0)

### *Foundational Architecture for AI-Augmented Software Engineering*

---

# 🔹 1. Purpose of This Blueprint

This document defines the **intended student experience and capability progression** across Semester 01 of the AAISE program.

It ensures that:

* courses function as a **coordinated system**, not isolated units
* student development is **intentional and cumulative**
* AI usage is **introduced, shaped, and stabilized correctly**
* foundational thinking patterns are **established early**

---

# 🔹 2. Semester Composition

### Core Technical Courses (Designed)

* Python Programming (10-152-117)
* HTML, CSS & JavaScript (10-152-118)
* Introduction to Algorithms (10-152-119)

---

### Supporting Courses (External)

* Introduction to Security (10-151-101)
* English Composition I (10-801-136)
* Introductory Statistics (10-804-189)

---

# 🔹 3. Student Entry State

Students entering Semester 01 typically:

* have little to no programming experience
* have inconsistent problem-solving confidence
* are unfamiliar with AI-assisted development
* expect learning to be:

  * step-by-step
  * answer-driven
  * tool-focused

---

# 🔹 4. Semester Exit Identity

By the end of Semester 01, students are able to:

> **Design, build, and explain simple software systems using structured thinking and appropriate use of AI tools.**

More specifically, students can:

* solve small problems programmatically
* build basic web interfaces
* understand and debug their code
* use AI as a tool without becoming dependent
* explain their work clearly

---

# 🔹 5. Core Capability Model

Semester 01 develops five foundational capabilities:

---

## 1. Problem Framing

* understanding what needs to be solved
* identifying inputs, outputs, and constraints

---

## 2. Construction

* writing code (Python)
* building interfaces (HTML/CSS)

---

## 3. Behavioral Logic

* implementing interaction (JavaScript)
* controlling program flow

---

## 4. Evaluation & Debugging

* identifying issues
* testing and refining solutions

---

## 5. AI-Augmented Development

* using AI tools appropriately
* evaluating generated output
* maintaining human control

---

# 🔹 6. Course Roles Within the System

---

## 🟦 Python Programming

**Primary Role:** Build logic and confidence

Students learn to:

* write programs
* understand code behavior
* use AI as a development assistant

---

## 🟩 HTML, CSS & JavaScript

**Primary Role:** Make systems visible and interactive

Students learn to:

* structure content
* design usable interfaces
* introduce behavior through JavaScript
* develop visual and usability awareness

---

## 🟨 Introduction to Algorithms

**Primary Role:** Refine thinking and decision-making

Students learn to:

* analyze approaches
* compare solutions
* reason about efficiency and structure

---

## ⚪ Supporting Courses (Contextual Roles)

### English Composition

* communication clarity
* structured expression of ideas

### Statistics

* reasoning with data
* interpreting patterns and results

### Security

* awareness of system constraints and risks

---

# 🔹 7. Temporal Alignment (Critical)

---

## Early Semester (Weeks 1–3)

Students:

* begin coding (Python)
* create basic web pages (HTML/CSS)
* learn course expectations (meta-frame)

Key Experience:

> “I can build something simple”

---

## Mid Semester (Weeks 4–8)

Students:

* gain control over structure and layout
* develop problem-solving patterns
* begin structured thinking (Algorithms)

Key Experience:

> “I understand what I’m doing”

---

## Late Semester (Weeks 9–16)

Students:

* integrate multiple concepts
* add interaction (JavaScript)
* refine solutions
* use AI more strategically

Key Experience:

> “I can build something real—and explain it”

---

# 🔹 8. AI Usage Progression (Cross-Course)

---

## Python

* introduced early
* used to reduce friction
* guided toward understanding

---

## Algorithms

* used with evaluation
* compared against manual reasoning

---

## Web Development

* delayed introduction
* used after design awareness develops

---

## Outcome

Students learn:

> AI is a **tool to support thinking**, not replace it

---

# 🔹 9. Debugging Progression (Cross-Course)

---

Students develop debugging skills progressively:

1. Visual debugging (layout and structure)
2. Console/logging (behavior tracing)
3. Tool-based debugging (browser/dev tools)
4. AI-assisted debugging (interpretation and refinement)

---

# 🔹 10. Learning Model (Shared Across Courses)

All technical courses follow a common pattern:

> **Think → Build → Evaluate → Adapt**

---

Students:

* think before acting
* build with guidance
* evaluate results
* adapt based on feedback

---

# 🔹 11. Student Experience (Emotional Trajectory)

---

## Early

* uncertainty
* curiosity
* initial overwhelm

---

## Middle

* growing confidence
* recognition of patterns
* reduced anxiety

---

## Late

* capability
* ownership
* clarity

---

# 🔹 12. Design Principles (Program-Level)

---

### 1. Confidence Before Complexity

Students must feel capable early

---

### 2. Structure Before Optimization

Understanding precedes efficiency

---

### 3. Human First, AI Second

AI supports—not replaces—thinking

---

### 4. Visibility Reinforces Learning

Students must build things they can see and interact with

---

### 5. Alignment Across Courses

Each course reinforces others

---

# 🔹 13. System-Level Outcome

At the end of Semester 01, students are not experts.

They are:

> **capable beginners with structured thinking and controlled use of AI**

---

# 🔹 14. Strategic Importance

This semester establishes:

* learning patterns
* AI interaction habits
* confidence levels
* problem-solving approaches

---

It determines whether students:

* become dependent on tools
  or
* become capable engineers
